# 自定义终端键：本机冲突审核 v1

状态：2026-09-04，Apple 共用存储／iOS SwiftUI 界面与 Android Keystore/DataStore／Compose 界面已实现。网络写入仍关闭；没有导入入口时，正常纯本机编辑不会凭空产生并发分支。测试使用隔离的内存或随机账户配置。

## 用户可见规则

1. 归一化后同一 ID 超过一个修订即为待处理冲突，包括编辑/编辑、编辑/删除和删除/删除。即使两个版本的文字相同，也不凭文字猜测因果关系。
2. 冲突按键不进入可发送键栏；管理页显示待处理数量、名称和版本数，打开后展示完整内容、分组及删除记录。版本编号只用于区分，不暗示先后或推荐版本；不展示或导出账户标识、actor、时钟和凭据。
3. 默认不选择版本；用户选择一个有效版本或删除整个按键，然后经二次确认提交。取消不更改配置。包含回车/换行的内容继续显示执行风险提示；处理冲突本身不发送字节。
4. 确认后选定内容及原顺序被保留，其他并发分支由因果后继取代；删除则保留墓碑。此操作不是永久历史归档，也不是可无条件撤销的备份。
5. iOS 使用原生 Form/List/Alert；Android 使用原生 Compose Material 对话、单选语义和滚动内容。大字体、多版本仍须可访问最后选项及确认按钮。

## 写入与安全边界

- 纯领域接口比较用户看到的**完整归一化冲突快照**；新增、替换、遗漏分支，或已经解决的快照均拒绝。不接受凭空构造的候选，也不能把墓碑作为“保留内容”提交。
- 解决时汇总全部已观察时钟并增加本机 actor 的计数。旧快照重放不复活删除，也不重建已解决冲突；其他 ID 不变。容量超限整体失败，不裁剪。
- 普通保存/删除不能绕过冲突审核。同名不同 UUID 不在这一规则中合并。
- Apple 额外检查账户租约和整份持久字节；外部文档改变或写入失败后禁用旧快照，原数据保持，显式重读恢复。不是跨进程数据库 CAS。
- Android 审核票据包含仅在内存中存在的随机租约标识，不能跨锁定、同账户重解锁、账户代次或重读复用。DataStore 事务内重新读取并比较冲突，验证新密文后一次替换；失败不提交。迁移原文保留，解决冲突计入编辑次数，不能再用迁移回滚覆盖新进度。
- Android 重读以原子租约续期重新启动已失败的数据流，不能在锁定后重新授予权限；错误提示绑定原租约，不泄漏至下一账户。只读取/重试，不清应用数据、不生成替代解密密钥。
- Android 本机文档同样拒绝重复及转义同名 JSON 字段，包括迁移编辑计数，避免歧义文档绕过回滚保护。
- UI 展示的按键内容可能由用户保存了敏感值；不新增日志、剪贴板、临时明文文件或遥测。这里不承诺托管内存物理擦除。

## 后续受保护恢复阶段（尚未开放）

同日更新：以下第 1 项及有效库的第 2/3 项已实现，见 [受保护恢复包 v1](key-recovery-package-v1.md)。损坏原始源的救援和重建仍未开放；下文保留阶段拆分，不表示当前有效库导出/导入尚未实现。

1. 定义独立、版本化、跨 Swift/Kotlin 的受保护恢复包；先确定加密、认证、密钥来源、口令成本、文件大小和未来格式保留策略。
2. 有效库导出只包含按键修订；损坏旧源的救援需独立的不透明受保护载荷，不能把解析失败的数据当作空配置。不可读取的系统密钥无法凭导出按钮恢复。
3. 导入先解密验证、预览差异并明确确认；仅在当前账户租约下原子提交，不覆盖现有进度。文件选择器取消、错误口令、篡改、跨账户/跨设备及空间不足需双端回归。
4. 导出/恢复未完成前，不提供明文导出、自动重置或清数据捷径，也不提前开启 E2EE 云端写入。
