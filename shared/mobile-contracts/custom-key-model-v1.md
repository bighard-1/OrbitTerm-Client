# 自定义终端键 v1：领域模型与迁移预检

2026-09-04。Apple / Android 已实现纯模型及自动回归；**没有接通 E2EE 上传、自动迁移或 iOS 编辑器**。Windows 仍是上一阶段只读识别，不消费 v1 内容。

同日后续状态：Android 已接入有效旧配置的加密原子迁移，见 [本机存储实现](android-key-storage-v1.md)；本文模型与预检 API 仍为纯函数，迁移提交由存储层负责。Apple 存储/编辑器及跨端 E2EE 上传仍未接入。

## 密文内模型

根对象只有 `kind`、`version`、`payloadSyntaxVersion`、`revisions` 四个字段，前三者分别为 `terminal_custom_keys`、1、1。

每个 revision：

- `id`：原按键 UUID，要求 36 位规范小写格式。无效旧身份不会自动重建或丢弃，迁移预检整体阻断。
- `clock`：actor UUID → 正整数计数。每个按键有自己的因果时钟，**不是**现有上传接口的 `vector_clock`，不能代替服务端 CAS/幂等保护。
- `value`：`{label,payload,section,order}` 或显式 `null`。`null` 为墓碑；缺少 value 是无效结构。

将原提案中的 entries/tombstones 统一成 revisions，是为了把并发编辑和删除放在同一套因果比较规则中；不会靠两个数组的遍历顺序决定是否复活。

`section` 只允许 common/symbols；`order` 为 0–1,000,000。标签为 1–16 个 Unicode 标量，不得全为空格 U+0020，不接受控制符、行/段分隔符和孤立 UTF-16 代理项。payload 继续使用既有 UTF-8/转义字节规则，不规范化、不展开 shell。当前 Android 新增标签输入不再用 UTF-16 截取，以免截断 emoji。

边界：最多 64 个含编辑值的逻辑 ID（冲突项也占用容量）、256 个总 revision（包括墓碑）、同一 ID 最多 8 个并发版本、每个时钟最多 32 个 actor；计数范围 1–9,007,199,254,740,991；JSON 上限 256 KiB。超过任何边界都阻止合并或编辑，不截断、不清墓碑。

## 合并及冲突

1. 两侧快照先独立校验；未知字段/版本、重复 JSON 字段（包括转义同名键）、畸形字段和无效字节拒绝进入可写模型。原文保留职责属于后续存储层，失败绝不能转换成空配置保存。
2. 同一 ID 下，完全相同的修订幂等去重；相同时钟但不同内容判为修订碰撞，整体拒绝。Swift 值比较使用 UTF-8 字节，避免其默认 Unicode 等价比较吞掉 Kotlin 认为不同的 payload。
3. 时钟所有分量不小于另一版本、且至少一项更大，才判为因果后继。只淘汰被后继覆盖的修订；不使用系统时间。
4. 并发编辑保留双方；并发删除/编辑保留墓碑与编辑值。任一 ID 存在多个保留版本时不生成可发送按钮，即使双方值碰巧相同也不替用户解决。
5. 明确编辑/删除/解决冲突时，必须已经观察该 ID 的全部版本。合并各 actor 最大计数后递增本 actor，产生支配所有已观察版本的新修订。旧版本重放不会复活已解决的删除。未来消费者必须先完成该账户全量拉取，不能拿部分增量页调用替换接口。
6. 展示顺序为 section → order → UUID，避免依赖不同设备语言的排序结果。结果修订按 UUID 和规范时钟键排序；在不触发容量或碰撞拒绝的范围内满足交换律、结合律、幂等律。

JSON 整数值允许等值的指数/小数写法（如 1e0/1.0），但不允许数字字符串、布尔值、小数值或溢出；Kotlin 使用精确十进制转换，不经 Double 舍入。编码仍输出整数。

## Android 旧配置

`TerminalCustomKeyMigrationPlan.inspect` 直接检查原始 preference JSON，而不是只检查 UI 可见列表。返回完整 Ready 快照或 Blocked 原因，不返回部分结果，不持久化，也不改变迁移标记。

- 保留原 UUID、标签、payload、分区和原数组顺序；使用调用方传入的 actor 初始化各键计数 1。
- 重复 ID、未知字段/分区、非法身份、旧非法 payload、超限等任一问题阻断整个预检。
- 原文缺失表示未配置；损坏、空字符串、JSON null 均不冒充空数组。
- 旧 DataStore 保存/删除路径另行加固：读到损坏/未知结构/重复身份时事务失败，不能从空列表重写；仅 UI 不可见但结构可读的旧记录随无关编辑原样保留其字段值。没有把它们按新 v1 规则静默清除。
- UI 写入失败保留输入、原配置及错误提示；写入期间禁用重复提交。只有成功后清空编辑内容，取消单独传播。错误提示不显示 payload 或异常正文。

## 尚未完成的发布条件

1. actor 必须在账户隔离的安全存储中稳定保存；备份恢复/克隆不能让两个设备复用可冲突计数身份。当前模型不替调用方生成/管理 actor。
2. 设计加密新存储、原始备份、原子提交/回滚及迁移完成标记，切换账户/锁定拒绝迟到结果；本轮预检不会启动迁移。
3. iOS 原生编辑器、冲突选择/恢复/导出界面；Android 同样需有修复或导出被阻断旧记录的入口。
4. E2EE 全量拉取、冲突重试、服务端 CAS 和写入开关；Windows/Linux 及已发布旧移动端的最低兼容版本/升级策略。
5. 完整跨端离线同步、重启、账户切换、密码轮换、容量耗尽的集成验收。纯模型测试不代替这些验收，也不自动提高整体产品完成度。
