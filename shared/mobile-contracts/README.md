# 移动端最后两项对齐契约

日期：2026-09-03。本文区分已落地的客户端规则与尚未启用的协议提案。
后端已于本轮通过 `/Users/cwz/Desktop/OrbitTerm-Master` 源码核实：`GET /api/v1/auth/recovery-info` 公开返回 `support_contact`；配置上传接口仅保存密文，不检查密文内部种类。
不得因服务端允许通用密文上传而推断旧客户端能够安全识别新的配置种类。

## 已实现：终端发送字节 v1

- 原文按 UTF-8 编码；不得逐个 UTF-16 code unit 编码。Android 拒绝孤立代理项。
- 转义仅允许 `\t`、`\r`、`\n`、`\e`、`\\`、`\xNN`；NN 必须恰为两个 ASCII 十六进制数字。拒绝正负号、Unicode 数字、不完整转义与未知转义。
- 解码后 1–64 字节；编码源最多 256 UTF-8 字节。64 字节的全十六进制表示也应允许输入。
- 不进行 shell 展开、Unicode 规范化或二次转义；回车、换行可能执行命令，保留现有编辑器警告。
- Android 编辑、新增存储入口和发送均复用领域层规则。旧版非法内容仍在管理列表保留，不生成可发送按键；新增其他按键不会因新规则过滤而把这些旧内容从持久存储删除。
- Apple 解码器与 Android 使用同一份 `v1-vectors.json` 进行自动回归；Apple 本机编辑器已接入，跨端同步仍未启用。

## 已实现：管理员联系地址安全边界

- 两端均通过现有公开 recovery-info 接口读取支持邮箱，离线默认地址为 `orbitterm@163.com`。不发送登录令牌、主密码或账户信息，只消费支持地址字段，不把恢复策略说明当成客户端安全规则。
- 地址最多 254 ASCII 字符；local-part 最多 64 字符，仅允许字母、数字、点、下划线、加号和连字符，拒绝连续点/首尾点。
- 域名至少两段，各段 1–63 字符，只允许 ASCII 字母、数字和连字符，拒绝首尾连字符，域名转小写、local-part 保留大小写。
- 这是产品配置白名单，并非完整 RFC 邮箱解析器；不支持的合法特殊邮箱必须先扩展双端测试，不能直接放宽其中一端。
- 拒绝完整 URL、查询、片段、百分号编码、换行与空白；无效配置回退默认地址，不直接插值成 URI。
- 两端邮件主题为“OrbitTerm 反馈”。iOS 使用 URLComponents，Android 使用原生 Uri/Intent。
- 邮件应用无法打开时均提示“未找到可用的邮件应用，可复制邮箱后发送。”并提供“复制邮箱”，仅复制公开支持地址。

## 待确认/未启用：自定义按键 E2EE v1

2026-09-04 更新：已完成 Apple/Android 领域模型、确定性冲突合并、Android 有效旧数据原子迁移，以及 Apple Keychain 本机存储和 iOS 原生编辑器，见 [模型 v1](custom-key-model-v1.md)、[Android 存储](android-key-storage-v1.md)、[Apple 存储](apple-key-storage-v1.md)。下表为早期提案；实际模型将 entries/tombstones 统一为带显式空 value 的 revisions。网络写入仍未启用。

同日最新：双端已接入冲突说明、完整版本审核、显式保留/删除和安全重读，见 [冲突处理 v1](custom-key-conflict-review-v1.md)。之后接入有效按键库的原生受保护文件导出、跨 Swift/Kotlin 解密、导入差异预览与确认合并，见 [恢复包 v1](key-recovery-package-v1.md)。再完成 [原始配置只读加密救援](key-rescue-package-v1.md)，保全未知/损坏原文，并只对来源仍一致且结构可枚举的内容显示逐条诊断，不将其当作可直接导入的有效库。修复决策/写回、旧端兼容发布安排和跨端上传仍未完成。文件导入可以产生真实并发分支，但不伪造云端冲突或同步状态。

建议以独立种类 `terminal_custom_keys` 封装在现有账户级 E2EE 配置机制中，不改变已有资产/密钥信封，也不把发送内容作为明文元数据上传。

拟议密文内字段：

| 字段 | 约束 |
| --- | --- |
| kind / version / payloadSyntaxVersion | `terminal_custom_keys` / 1 / 1，未知版本只保留不覆盖 |
| entries | 每项 UUID、标签、原始转义内容、common/symbols 分区、顺序、逻辑修订身份 |
| tombstones | 删除项 UUID 和逻辑修订身份；没有服务端确认水位不得自动清墓碑 |
| revision | 复用现有账户配置版本/冲突控制；不得仅靠设备墙上时间决定胜负 |

实施顺序与验收：

1. 确认服务端允许该种类，并验证所有仍受支持的客户端会跳过/保留未知种类而不把它误认为资产，不会把解密错误当成空配置上传。
2. 确定每账户按键数、标签长度、墓碑容量与排序冲突规则；提议最多 64 个活动项、标签最多 16 个 Unicode 标量。现有超限记录不得静默截断。
3. 完整拉取成功后才允许合并。冲突时同一 UUID 的并发编辑保留双版本供用户选择；并发删除/编辑不能静默复活。新建同名不同 UUID 项不丢弃。
4. Android 首次迁移保留原 UUID 和原始内容，失败时保留本机原配置；旧版不接受的记录必须可导出/修复，不删除。
5. iOS 原生编辑器仅在协议和安全本机存储接入完成后开放；锁定/登出清除解密缓存，账户切换阻断迟到回调。运行状态与按键使用计数不同步。
6. 发布门禁：A→B→A 字节完全一致、重启恢复、离线并发编辑/删除、旧客户端兼容、账户切换、未知版本和超限输入隔离；不连接真实服务器执行自定义命令。

## 已实现：管理员配置 API 与缓存

- 已核实路由：`GET /api/v1/auth/recovery-info`，无需认证，限流 60 次/分钟；响应为 `{"success":true,"data":{"support_contact":"…"}}`。管理端在恢复策略中维护该字段；后端不保证字段为邮箱，客户端仍执行白名单校验。
- 证据：后端 `internal/router/router.go`、`internal/controller/auth_controller.go:RecoveryInfo`、`internal/service/recovery_policy_service.go:PublicRecoveryInfo`。本轮未修改后端及其已有未提交文件。
- 现有响应没有 revision/TTL 字段，客户端采用固定 24 小时缓存、5 分钟最短刷新间隔；只在相关前台生命周期刷新，后台取消，回到前台重新校验过期。
- 缓存只存服务地址、已验证邮箱和获取时间。该接口是同一服务对所有用户公开的数据，故按后端来源隔离，不额外绑定账户，更不会因为刷新失败而操作登录会话。
- 进程内缓存年龄使用 uptime；重启用保存的墙钟时间恢复，未来时间戳或已过期记录不能使用。无效响应不覆盖最后有效缓存；成功响应省略或清空该字段表示恢复默认地址。
- Apple 服务地址变更后拒绝旧请求迟到结果；Android API 实例的来源不可变，新实例拒绝其他来源的缓存。请求取消不得发布结果，也不延后下次前台重试。
- 已有缓存/接口自动化覆盖：有效/失效缓存、断网、错误信封、URL 注入、来源切换、迟到响应、取消与无认证请求。无邮件应用的原生页面仍保留人工模拟器验收项。

## 自定义键同步当前兼容风险

历史版本没有自定义键类型分流，可能尝试作为资产解析并误报解密失败。本轮已为当前工作区的 Apple（iOS/macOS）、Android 和 Windows 增加只读预留；这不会改变已发布旧二进制的行为，也不代表已完成所有旧端兼容。

### 已实现：只读预留与资产隔离

- 仅精确识别 JSON 对象的字符串 `kind: terminal_custom_keys`；大小写、前后空格、嵌套字段均不容错。其他未知种类不因此获得可跳过的权限，Windows 保留未知类型阻断/不确认的行为。
- 此阶段只识别种类，**不校验版本或 entries**。未知、缺失、甚至畸形版本均不会被执行、合并或改写；未来真正的按键消费者必须单独校验其完整模式。类型识别不等于数据有效。
- 必须没有 `asset_id`（null/字段缺失）；空字符串也不接受。携带资产身份的保留类型拒绝走资产解码，不允许用服务器身份挂接账户级配置。未来删除单个键应使用密文内 tombstones，不借用服务器资产删除接口。
- Apple 全量/增量资产准备和 Android 资产拉取/冲突候选均绕过合法预留记录；不计入解密失败，不写资产凭据，不进入资产去重/删除候选。辅助配置单独存在时不会误报主密码不匹配。
- Windows 对预留类型不上传、不应用为资产，允许确认其同步页；混合资产页继续应用正常资产。无 asset_id 的已删除记录若仍含可解密预留内容，也能安全越过；无法解密/无法识别的无身份墓碑仍阻断，不猜测删除目标。
- “保留”是保持服务端原密文不修改、不删除，不是建立本机解密副本。后续开启自定义键同步必须独立全量拉取，不能认为历史增量确认意味着已缓存按键。
- 自检三端主密码轮换与 V2 迁移实现：均解密原文并直接重新加密，不解码后重建 JSON。Apple 新增原生加密字节往返回归；Windows 实际轮换控制器测试覆盖 V2/legacy、active/deleted、未知版本和原字节保留。尚未将 Android/Apple 的完整轮换网络流程算作本轮端到端验收。
