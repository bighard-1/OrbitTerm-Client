# 自定义按键原始配置救援包 v1

状态（2026-09-08）：iOS / Android 原生只读导出、回读核验与逐条修复预览已接入。它是保全和检查原始数据的工具，**不是有效库备份、不是修复器、不是清库/重建许可**。不修改本机存储、不读取登录/主密码/资产凭据仓库、不发送命令、不上传应用服务器。macOS 覆盖共用核心编译/测试，没有新增桌面入口。

## 原始数据与访问边界

- iOS：在当前账户已解锁租约下重新读取专用自定义按键 Keychain 条目的 Data，原样封装，允许非法 UTF-8 / 未知 JSON；Keychain 读取失败或条目不存在则拒绝。不把读取失败等同于零字节条目。真实存在的零字节条目可以原样救援。
- Android：直接只读同一次 DataStore 快照中的 protected、legacy、paused 三个本账户字段；同时存在时全部保留，不择一、不迁移、不解析、不调用 Keystore 加解密。字符串按原始 UTF-16 code unit、大端顺序封装，**不使用会替换孤立代理项的字符串编码器**。不存在的字段不写入；paused 单独存在不能视为可救援按键库。
- 加密前后校验当前解锁租约；加密结束后再次读取并比较全部来源。账户切换、锁定、重读使旧页面/结果失效；来源变化需要重新导出。系统文件选择器只收到加密字节。
- 原始数据累计上限 4 MiB，超限拒绝，不截断。不生成空库替代，不轮换/删除任何设备密钥。DataStore 本体不可读时也无法救援其中字段。
- Android 缺失 Keystore 密钥时可以保全现存**密文字符串**，不能因此解密它。救援包不导出硬件密钥；换设备不保证救回原密文。iOS 已读出的自定义键原文由独立口令包裹，但不能把源损坏内容自动解释为合法按键。
- 独立口令要求与有效备份一致。文件可能包含用户写入按键中的敏感内容、旧版本数据、匿名账户摘要和本机元数据；不会筛除或自动修正这些内容。不得卸载/清除应用数据来“配合修复”。

## 二进制格式

扩展名 `.orbrescue`，外层 magic 为 8 字节 ASCII `OTKEYRS1`。其余与有效备份加密容器相同：salt 16 字节、nonce 12 字节、AES-256-GCM ciphertext、tag 16 字节；头部 36 字节全部为 AAD；PBKDF2-HMAC-SHA256 固定 600000 次。系统随机源，每次独立盐和 nonce。普通 `.orbkeys` / `OTKEYBK1` 解析器拒绝救援包，救援解析器也拒绝普通备份，不能靠改扩展名绕过。

解密后的二进制载荷：

1. platform：1 字节，1=Apple、2=Android。
2. account：64 字节小写十六进制 ASCII，源账户 storage identifier（不是用户名，也不是所有权证明）。
3. count：1 字节，1..3。
4. 按 tag 升序排列的 count 条来源：tag 1 字节、length 4 字节无符号大端、原始 bytes。

| tag | 内容 | 平台 / 约束 |
| --- | --- | --- |
| 1 | Keychain 自定义按键条目的原始 Data | Apple，必须且只能有该项 |
| 2 | protected 密文字符串的 UTF-16BE code units | Android，可选，偶数字节 |
| 3 | legacy 字符串的 UTF-16BE code units | Android，可选，偶数字节 |
| 4 | paused 的原始布尔值 | Android，可选，恰好 `00` 或 `01` |

Android 至少含 tag 2 或 3。拒绝未知平台/标签、重复或乱序标签、负向/超界长度、尾随数据、奇数字符串字节、无效布尔值和超限总量。载荷上限保守固定为 `4 MiB + 85`，加密包上限再加 52 字节；不读取来源中的任何“声明大小”来分配无限内存。测试使用独立 Node/OpenSSL 已知答案，两端均核对同一载荷和加密包，含非法代理项及截断 JSON；测试样例不进入正式 APK/App。

## 交互与不能宣称的保证

管理页存在存储警告时显示“原始配置加密救援”，说明只读性质、不可直接导入、保留本机数据及设备密钥；要求独立口令及再次确认。页面不提供选择导入、合并、重建或删除操作。普通备份页失败不会自动切换成救援模式。

### 回读核验报告

用户必须通过原生文件选择器重新选择 `.orbrescue` 并再次输入该文件口令。客户端先执行大小、magic、PBKDF2/GCM 认证和严格载荷校验，认证前不解释来源内容。成功后仅显示下列有限元数据，不显示标签、按键载荷、旧 JSON、密文、账户名或原始摘要：

- 来源平台、源账户摘要是否与当前已解锁账户一致；摘要一致只表示本地作用域相同，不是身份所有权证明。
- 若来源与当前平台相同，重新读取当前专用存储并逐字节比较整个来源集合，显示一致、已变化、或当前来源不存在/不可读取。不同平台显示不可比较，不把不同本机格式误判为数据变化。
- 每个来源的类型、原始字节数和有界诊断。Apple 仅区分可通过完整本机文档契约与不可通过；解析在后台执行。Android 的 protected 仅区分“本设备可解密且完整验证”与“无法解密或验证”，不能在密钥不可用和密文损坏之间给出未经证明的结论；legacy 可区分结构无效、重复 ID、契约拒绝、或结构完整可迁移；paused 仅确认标记完整。
- 外部平台来源只显示为已认证不透明数据，本平台不解释。未知版本、截断结构或密钥不可用都不会给出“可以重建”的结论。

核验前后再次检查账户租约和当前来源快照；期间变化则报告失败并要求重新核验。选择新文件清除旧报告；成功后清除页面口令。报告只存在当前页面内存，不保存、不上传、不可作为后续写入授权；关闭、锁定、换账户或重读会丢弃报告。Android 对救援来源的临时 byte arrays 做尽力清零，但不承诺托管运行时的物理内存擦除。

### 逐条修复预览（仍为只读）

逐条预览只在来源平台与本机一致、源账户摘要与当前解锁账户一致、且当前专用存储和救援来源逐字节一致时生成。iOS 仅枚举 Apple 本地文档的 revisions；Android 仅枚举 legacy 数组，protected 密文仍保持不透明。不同平台、账户不符、来源缺失或已变化时不生成预览。Android 同时存在 protected 与 legacy 时明确显示来源冲突，后续不得直接覆盖 protected。

- JSON 损坏/截断、重复键、根结构不可枚举或超过 256 项时整体阻断，不做半截预览；未知文档版本和元数据只作为文档级问题显示，不声称可以写回。
- 每项只显示从零开始稳定编号、经转义并最多保留 24 个 Unicode scalar/code point 的 ID/名称/分组摘要，以及发送内容的 UTF-8 字节数。控制字符、格式字符、双向文本控制符和反斜杠会被可见转义；不显示原始 payload、JSON 或密文。
- 逐项状态只有“可原样保留”“需要人工修正”“需要容量取舍”“无法解释”。缺失/错误字段、非法 ID/名称/payload/分组/时钟、版本碰撞、单项超过 8 个版本，以及活动项目超过 64 项都会明确列出。超过容量时不擅自选择前 64 项。
- “可原样保留”只说明该行符合当前项目契约，不代表整个文档可恢复；文档级元数据问题、Android protected 并存等全局阻断仍优先。预览对象不包含原始发送内容，也不产生修复后文档、排除清单、确认令牌或任何存储写入函数。

选择器取消不写本机配置。目标写出失败可能残留不完整密文文件，不能视作成功备份。保存成功仅表示系统提供方接受了写出，不表示第三方云盘已经可靠持久化，也不表示救援内容可修复。已经交给文件提供方的密文无法保证在锁定/关闭后撤回。沿用 Android 现有文档交互锁定宽限，不更改全局锁定政策。

## 下一阶段

下一阶段先设计显式修复决策的数据模型与二次确认约束，仍不默认开放写回。只有原始救援包重新读取解密核验、来源仍一致、所有人工修正/排除/容量取舍逐项确认、修复结果完整再预览，并保留可验证回滚材料后，才可能评估原子替换。未知版本、截断结构、protected 设备密钥缺失或来源冲突不能猜测重建；任何排除都必须明确告知数据损失。当前代码仍没有修复写回/重建接口。云端 E2EE 写入保持关闭。
