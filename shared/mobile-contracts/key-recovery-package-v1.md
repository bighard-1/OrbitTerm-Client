# 自定义终端键受保护恢复包 v1

2026-09-04。范围：有效本机按键库的原生加密导出、跨 Swift/Kotlin 解密、导入差异预览和确认合并。不是云端同步、凭据转移或损坏存储重置工具。

## 格式与密码学

文件建议扩展名 `.orbkeys`，MIME `application/octet-stream`。文件名不包含用户身份、服务器名或时间线信息。固定二进制布局，所有偏移以字节为单位：

| 偏移 | 长度 | 内容 |
| --- | --- | --- |
| 0 | 8 | ASCII `OTKEYBK1`（格式、算法、KDF 成本固定的版本标识） |
| 8 | 16 | 系统密码学随机盐 |
| 24 | 12 | 系统密码学随机 GCM nonce |
| 36 | 可变 | AES-256-GCM 密文 |
| 文件末尾 - 16 | 16 | 128 位 GCM 认证标签 |

- 密钥派生：PBKDF2-HMAC-SHA256，600,000 次，输出 32 字节。口令按精确 UTF-8，不 trim、不进行 Unicode 规范化；至少 12 个 Unicode 标量，最多 256 UTF-8 字节，拒绝控制字符、纯空白及 Android 孤立代理项。不得用简单 SHA256 代替 KDF。
- 每次导出重新生成盐和 nonce。AAD 是整个前 36 字节；替换版本、盐、nonce、密文或标签均不能成功认证。未认证前不解释 JSON。
- 格式不接受文件提供的任意算法或迭代次数；未来版本必须另行审核。最大文件 262,196 字节，等于信封上限 262,144 + 52；有界流式读入，超限整体拒绝，不解压、不加载 ZIP、不执行终端内容。
- Apple 使用 CommonCrypto PBKDF2、CryptoKit AES.GCM 和 SecRandom；Android 使用 JCE PBKDF2/AES.GCM 和 SecureRandom。没有引入加密依赖，也没有自行实现密码学算法。
- 600,000 次是本格式选择的固定成本，与 [OWASP 的 PBKDF2-HMAC-SHA256 指引](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html#pbkdf2)一致；这不构成 FIPS 认证或口令强度保证。该可离线复制文件仍依赖用户使用独立、足够强的口令；忘记口令不能恢复。旧文件不会随应用内主密码轮换而重加密或失效。
- 敏感数组在可控范围内清零，但不承诺 Swift/Kotlin 托管 String、系统密码组件或编译器临时副本的物理擦除。派生和加解密不在 UI 主线程执行；取消/锁定撤销结果发布，已进入本机 KDF 的计算可能执行到结束。

## 加密载荷与可移植性

载荷仅是共享 `terminal_custom_keys` v1 信封的 UTF-8 JSON，包含修订/因果时钟/墓碑/冲突及按键内容。**不包含本机文档 wrapper 的 account、writer actor、originalLegacy、edits，不读取登录令牌、主密码或资产凭据仓库**。按键内容若由用户自行保存了敏感文本，仍会被包含在加密载荷中；不宣称备份能自动识别或剔除这些文本。

修订时钟中的匿名 actor 必须保留以保持因果历史，但目标客户端保留自己的本机 writer actor，不能克隆源设备的写入身份。文件可由持有独立口令的用户导入**任意当前已解锁账户**；这是显式迁移功能，不隐含源账户所有权认证。文件与口令应分开保存。

共享 `key-recovery-v1-vector.json` 由独立 Node/OpenSSL crypto 实现生成，固定测试盐/nonce 与中文 emoji 口令，只用于已知答案测试。分别覆盖 Swift 排序 JSON 和 Kotlin 字段顺序；两端既核对本端导出字节，也解密两种顺序。正式 APK/App 不包含测试样例，不使用固定随机源。

## 导入事务

1. 使用系统文件选择器读取文件，不申请整盘访问权限，不保留永久 URI 授权，不自动上传或分享。
2. 验证格式、长度、口令和认证标签；严格验证 JSON 模式、版本、重复字段、字节/容量/actor/计数上限。解析失败不是空库。
3. 以完整本机快照进行因果合并。显示每个变化 ID 的当前/合并后内容、分组、顺序、删除记录，以及最终可发送数量和冲突数量。文件缺少的本机 ID 不被删除，较新的墓碑仍可能删除本机旧版本，故必须预览并明确确认。
4. 预览只读；取消不写入。无变化不提交；较旧备份不复活被后继删除的按键。并发修改继续进入冲突审核，不自行选择赢家，不发送任何内容。
5. 确认绑定原账户解锁租约。Apple 同时比较归一化预览基线和持久原始字节；Android 同时比较租约、原密文 SHA256 指纹及重新计算的合并结果。预览后任何持久变化都需重新预览。
6. 保留本机 writer actor、Android 迁移原文；更新整个本机保护文档。Android 计入编辑次数，不能再回滚迁移覆盖导入进度。超限、坏库、缺失密钥、写入失败不执行部分恢复。

导出/导入界面的口令只保留在当前页面内存；锁定、切换账户、关闭页面后清除 UI 状态并取消工作。文件选择器迟到回调不能在新账户继续工作。仅加密文件交给系统文档提供方；提供方可能是用户选用的云盘，应用不在自身临时目录生成明文备份。写出失败可能留下不完整密文文件，界面明确提示不要将其作为有效备份。

Android 复用现有文档交互的 **2 分钟**后台锁定宽限，不修改全局锁定政策；超时仍锁定。选择器启动失败立即撤销本次宽限。管理/恢复页面位于活动终端条件之外，避免文件选择器返回时短暂空会话快照销毁页面；无活动终端也能管理/备份按键。已进入提供方的加密文件写出可能完成，关闭页面并不保证撤销提供方已经收到的字节；不会继续发起迟到的新写入。

## 有意保留的限制与后续

- 不把未知/损坏/超限旧配置转换成“有效空库”，也不允许导入覆盖无法读取的本机库。同日后续已实现 [只读原始配置救援包](key-rescue-package-v1.md)，与本有效备份格式严格区分；救援回读及有界逐条诊断已开放，但显式修复决策与经过备份核验的重建仍未开放。
- 系统 Keychain/Keystore 丢失或不可读时，无法导出其中无法解密的内容。之前已成功导出的便携文件仍能在新的可用安装内、经用户解锁与口令验证后恢复。
- macOS 共用模型、加密和本机事务编译/测试覆盖；本轮只新增 iOS 与 Android 原生恢复页面，没有额外添加 macOS 页面。
- 需要人工模拟器/后续设备验证不同 Files/文档提供方、目标目录权限、取消/存储空间不足和锁定行为。不以单元测试或本机文件回环宣称已验证所有第三方云盘、真机或断电情况。
- E2EE 网络写入仍关闭，旧发布客户端/Linux 分支兼容安排不因本机文件互通而自动完成。
