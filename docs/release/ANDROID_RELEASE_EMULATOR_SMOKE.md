## 已完成的本机演练

- 从 Rust 源码构建 `arm64-v8a` 与 `x86_64` 的 `liborbit_core.so`。
- 执行 `check_android_release_gates.sh`：Release 混淆、资源压缩、ABI 拆分、native 调试符号检查、依赖锁定、单元测试与源码安全扫描通过。
- Android 15 ARM64 模拟器安装 arm64 Release 候选副本后，冷启动、前后台切换和热恢复均正常；未发现应用进程 Fatal Exception 或 native fatal signal。
- 仅使用临时测试签名副本以验证安装/启动路径；原始 Release APK 保持未签名，未被修改。
- 已启动独立、无数据的 Android 15 ARM64 模拟器，并仅安装从临时测试签名副本提取的 Release APK：冷启动正常，登录页的账号/密码输入、登录入口与本地解锁安全提示可见；注册入口可达，注册页的账号/密码/邀请码输入、密码规则与注册入口可见。未填写或提交任何账户信息，测试完成后已卸载应用并关闭该模拟器。
- 现已提供 `assembleSmoke`：它构建 minified、resource-shrunk、debug-signed 的 `com.orbitterm.android.smoke` 隔离包。该包已在 Android 15 ARM64 模拟器冷启动到登录页，登录/注册入口可见；卸载隔离包后，正式包及其数据未受影响。
- `run_android_smoke_fixtures.sh` 已在 Android 15 ARM64 模拟器通过：锁定、浅色主题、深色主题和无活动会话四个无数据状态均可见；每个状态在独立 smoke 进程中渲染，脚本结束后自动卸载隔离包。
- 隔离 smoke 回归还覆盖连接失败、同步失败、Docker 空列表与传输队列；均使用固定的脱敏展示数据，不会连接服务器、读取凭据或创建传输任务。
- Host Key 确认阻断、认证失败、网络离线、同步冲突以及传输失败/取消反馈也已纳入隔离 smoke 回归；这些夹具没有“信任”“重试”“解决冲突”等真实副作用。
- 在独立、无数据的 Android 15 ARM64 模拟器上完成 CI 等价的 connected 仪器化门禁：`core` 1 项与 `app` 12 项均为 0 failures / 0 errors，覆盖 Room 迁移、Compose 状态、性能预算与 UI 基线。
- UI 截图基线已改为固定 320×640、density 与 font scale 均为 1 的测试画布，不再依赖模拟器实际分辨率；已在 1080×2400 模拟器复测通过，避免不同设备尺寸造成误报。
- 本轮共执行 13 个隔离 smoke 状态夹具；脚本结束后自动卸载 `com.orbitterm.android.smoke`，未触碰正式包、正式账户数据或真实服务器。
- 原有模拟器保留既有“解锁工作台”状态。为不清除资产、也不输入主密码，未执行解锁后的锁定/解锁、主题切换和空态导航；这些项目记录为“未执行”，不是失败或通过。对应 UI 状态已有仪器化回归覆盖，但仍不等同于 Release 包的已登录交互验收。
