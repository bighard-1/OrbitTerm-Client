# Android K60 SFTP 真机专项（2026-10-20）

本日志只记录专用测试账户、隔离只读 SFTP 夹具和 Android 独立 QA 的脱敏证据。夹具仅暴露虚构文件，不提供 shell 或写入；测试资产为“仅此设备”，未进入账户同步。Windows 对照见 [Windows SFTP 暂停→取消专项](WINDOWS_SFTP_PAUSE_CANCEL_20261020.md)。以下“真实设备”指 K60 设备上的原生 QA，经 Mac 镜像操作；镜像可见 QA 是本轮临时包，不代表正式包安全策略。

## 初始候选与失败保留

- 源码基线 `64d04be`；K60 临时镜像可见 QA APK SHA-256 `99e94a5e1a16c7352fe7f3a9e7bf31142b75df6b1d63cfed2a78454e223a398c`。本轮之前安装的原受保护 QA APK SHA-256 `a89bbc2b8a8330545d2435d95c7cbee9cb9e18c0426476cff0fa12d3ca9d4063`。两包同测试签名、同 QA 包名，正式版未更新。
- K60 对隔离夹具首次 SSH Host Key 提示与本机独立夹具指纹一致后信任；SFTP 根目录可列出慢速测试文件。夹具拒绝 SSH exec 时资源卡显示“监控读取失败”，但 SSH/SFTP 连接与文件列表仍可用；这与 Windows 默认监控旧包“误断线”失败不同。
- 第一次慢速下载显示“下载中”，点击“取消传输”后却显示“文件传输失败：操作失败，请稍后重试。诊断代码：unknown”和“重试下载”，不是“已取消”。Android 系统下载目录出现 0 字节同名 SAF 目标文件。第二次从失败态重试后取消仍为普通失败，首次与复测失败都保留。
- 隔离夹具的 256 KiB 短文件可下载完成，K60 文件 SHA-256 与夹具一致：`8a39d2abd3999ab73c34db2476849cddf303ce389b35826850f9a700589b4a90`。因此不能把慢速取消失败泛化为 SFTP 下载全坏。

## 诊断与修复候选

- 受检 Rust FFI 返回宽泛 `sftp_download_failed`，并以稳定 `detail_code=sftp_transfer_cancelled` 区分用户取消。Android 桥接以前只取 `code`，随后错误映射把它降为 `unknown`，SFTP ViewModel 仅按 `OperationCancelled` 分类，最终把主动取消当失败。
- Android 桥接优先保留此取消明细码，其它下载/上传失败保留普通 SFTP 错误类别；下载取消或失败的文案提醒：系统文件选择器可能已在目标位置创建空文件。下载先写应用私有暂存、完成才拷贝到 SAF，但系统创建的目标 URI 属用户选择器管理，本候选**不擅自删除**目标文件。
- 源码修复提交 `8a61388`；Android `:core:testDebugUnitTest :domain:testDebugUnitTest :feature:testDebugUnitTest --offline --no-daemon` 通过，新增桥接取消分类、普通 SFTP 分类及取消提示单测。主工作树受保护 QA `:app:assembleQa -x :app:buildOrbitAndroidCore --offline --no-daemon` 通过；临时镜像可见修复候选同一构建命令也通过，APK SHA-256 `2486ce62ebba7989b069d17ed034aca76f7ccc40a0eaa6671cb150df142db86b`，与原 QA 包签名证书 SHA-256 `487967efa5c0fdd16f5d37be2c9bc0b959807da8a6a458e2788c23d000df0751` 相同。隔离 GUI 未做；K60 修复版真实设备取消复测见下文。**五端完整验收未完成**。

## 修复候选的 K60 真实设备复测与收尾

- 同签名镜像可见候选 `2486ce62…2db86b` 原位安装；用户在实体 K60 输入主密码解锁后，镜像操作隔离资产。SSH/SFTP 重新连接，文件列表可见。慢速文件显示“下载中／已传输 0 B”，点击“取消传输”后立即显示绿色非错误状态：“下载已取消。系统创建的目标文件可能为空，请在保存位置检查。”，未显示 `unknown`，未出现自动重试。**这只证明当前候选的主动取消路径**；未证明断网、远端中止或大文件完整下载。
- Android 下载目录仍有原轮产生的 0 字节虚构目标文件，短文件保持 256 KiB。系统保存器创建的 URI 未被客户端擅自删除，提示与观察一致。没有清理这两个系统下载目录文件，以免把应用外文件处理混入客户端验收。
- 测试资产 `ot-k60-sftp-qa-20261020` 从活动列表移除，当时依据旧确认文案误记为“仅本机软删、可在最近删除恢复”。**该判断已被后续实体 K60 观察和源码审查否定**；详见下节。此处保留误判经过，不再作为恢复能力证据。只读夹具当轮停止，端口无监听。
- 本轮结束覆盖安装**新构建的受保护 QA**（并非字节相同的旧 QA）：APK SHA-256 `65998a72d51708748616d0c42db92bd1835de7c0efdc646d86b7ff8a23d19d17`，与镜像可见候选同测试签名，设备 `base.apk` SHA-256 与该值一致。启动 QA 后 Mac 镜像为黑屏，符合 `FLAG_SECURE` 保护；正式版未修改。新受保护包尚未由用户在实体屏幕重新解锁/做 SFTP 业务验证，因此不把镜像黑屏视作业务通过。

## 后续对照与边界

- Android 本次已证明镜像可见同源候选的主动取消分类；下一轮在受保护 QA 实体屏幕核对相同提示，并覆盖断网、远端中止、重新发起、系统保存器同名文件和完整文件校验。若任一路径再显示 `unknown`，继续查 FFI 返回与客户端状态，不以单测替代真机。
- Windows `b921c58` QA 已在默认监控下验证 SFTP-only、暂停→取消、专用目录 0 文件；Android 目前只实现活动传输取消与队列暂停，不能声称功能完全对齐。Windows 仍需与 Android 对照普通失败/取消分类、目标残留、重试、断网和完整文件校验。
- Mac/iOS/Linux 同候选 SFTP 取消、五端完整验收、正式防镜像包均不由此次 K60 镜像可见 QA 证明。

## 受保护 QA 恢复尝试与本机删除语义纠偏

- 用户准备在 K60 受保护 QA 复测 SFTP 取消；按此前错误记录去“最近删除”恢复唯一虚构 SFTP 资产，实际**找不到该项**，因此未继续连接或下载。不能把这一轮记为受保护 QA 的 SFTP 业务通过。
- 源码核对：Android `AssetMutationRepository.delete` 对 `LOCAL_ONLY` 在本机事务内直接删除资产、清掉本机同步队列项，随后清除凭据；只有 `ACCOUNT_SYNCED` 才排入 `MOVE_TO_TRASH`。`SyncRepository.loadRecentlyDeleted` 仅请求云端删除记录，不存在本机回收站。因此该本机夹具资产不能通过应用恢复；此前“软删可恢复”的台账和操作引导是错误判断。未触碰真实资产，也未执行云端永久删除。
- 源码提交 `36f88ec` 修正编辑页/列表单条/批量/分组的删除确认与完成提示：本机资产明确警告直接删除、无法在应用内恢复；账户同步资产提示云端删除排队及同步后可见；混合范围分别说明。编辑页删除重新读取持久化资产，避免未保存的范围切换导致删错分区；仅本机删除不再触发无意义的云端同步。Android feature 四项新增单测、app 单测和受保护 QA 本机构建通过；arm64 APK SHA-256 `ea89e900a1c0f8810c4aa451a58f267c425cc1c8b3eae6962077194f8cb22312`，测试签名与前包一致。新 QA 已原位安装到 K60，设备 `base.apk` 哈希精确匹配；**新文案尚待实体屏幕核对，也没有隔离 GUI 结果**。
- 本轮短时只读 SFTP 夹具在发现资产不可恢复后已停止，端口无监听；没有重建资产或再次执行删除。后续受保护 QA 取消验收需新建独立虚构本机资产并启动新的隔离夹具，核对 Host Key、下载中取消反馈和 SAF 目标残留；现有受保护包的取消功能仍属未验证。五端完整验收未完成。
- 后续在受保护 QA 新建虚构资产时，K60 键盘遮挡并阻断字段录入；该失败及修复候选另见 [Android 资产编辑页键盘避让专项](ANDROID_ASSET_EDITOR_IME_20261020.md)。**不以模拟器通过替代 K60 复测，也不把本轮阻断记为 SFTP 取消通过。**
- 后续 K60 已安装键盘修复后的受保护 QA（APK SHA-256 `a35558792ccfabf55d966d313cbd1872ae34b31990659328aad6c761de375cec`）。用户在实体设备成功新建唯一虚构“仅此设备”SSH 资产；删除前确认框明确说明仅处理该资产、本机凭据同时清除、不会进入最近删除且无法在应用内恢复。用户随后确认执行删除，并检查“最近删除”中没有该资产。**本机直接删除语义及确认文案的这条真机路径通过**；完成提示原文与活动列表消失未单独回报，批量/混合/账户同步资产删除未由此证明。没有连接虚构 SSH 或真实资产，也未重建 SFTP 夹具；受保护 QA 的 SFTP 取消仍待测。

## 受保护 QA 的实体 K60 SFTP 取消复测

- 候选仍是上述受保护 QA APK `a35558792ccfabf55d966d313cbd1872ae34b31990659328aad6c761de375cec`，本轮启动前重新读取 K60 已安装 `base.apk` SHA-256，精确匹配。没有安装镜像可见包，也没有更改正式版、服务端或真实资产。只读隔离夹具沿用先前核实的临时主机密钥，只向测试网内限定设备开放，只有虚构短文件和慢速文件、无 shell 和写权限；Mac 自身 SFTP 列目录/读取块及 K60 到夹具端口连通性通过。
- 用户在 K60 本机新建独立“仅此设备”虚构 SSH 资产并连接；终端顶部显示“已连接”，但没有普通命令提示符、键盘无法输入。**这符合夹具明确禁用 shell 的边界**，不能把它记成真实 SSH 终端功能失败或成功。Mac 只读网络状态显示夹具与 K60 保持 TCP 连接。
- 用户进入受保护 QA 的 SFTP，按指引对慢速虚构文件开始下载、在“下载中”点“取消传输”；实体屏幕显示“下载已取消，系统创建的目标文件可能为空，请在保存位置检查”，未报告旧版 `unknown` 失败。Mac 经 ADB 只读检查本轮目标测试文件为 **0 字节**，与客户端警示一致。用户未报告自动重试情况，故不记为已排除；短文件校验属于之前镜像可见候选，不挪用为本轮受保护 QA 结果。
- 本轮测试完成后主动停止隔离夹具并核对端口无监听；0 字节目标文件未擅自清除，供需要时复核。**受保护 QA 的主动取消反馈通过，目标残留已确认**；断网、远端中止、重试、非空文件校验、Android 其他输入形态和五端完整 SFTP 验收仍未完成。
