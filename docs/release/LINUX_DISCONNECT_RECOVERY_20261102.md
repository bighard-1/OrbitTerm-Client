## 隔离GUI结果

两条授权虚构SSH会话均通过Host Key验证和SFTP读取。标签按UUID排序，短标签初次按位置预期的目标与实际次夹具不一致；随后用完整标签及目录重新确认。实际故障对象为次虚构会话，主虚构会话作为对照，未操作真实资产。

释放进行中显示“正在断开连接…”。点击主窗口关闭，应用仍保留，明确提示“SSH断开尚未完成，请等待完成或重试断开后再退出”。第一轮完成后显示“断开未完成”，标签保留，说明仍有资源未确认、需重试后才能重新连接；菜单“重试断开”可用、“重新连接／在新窗口打开”禁用，退出继续被拦截。

真实终端释放确认成功一次，剩余资源恰为SFTP和基础会话，没有提前丢弃所有权。故障期间另一会话仍在线，实际收到新增虚构shell标记，显式刷新SFTP读到新加标记文件（5项），不是只看旧缓存。

对故障标签选择“关闭标签”，保存关闭意图并触发第二轮结果通道中断；5秒后仍保留原标签，重试再次可用，重连仍禁用。第三轮显式重试使用真实释放：SFTP成功、剩余句柄全空，已确认终端没有重复关闭。原故障标签此时才消失，另一会话仍选中、在线，终端历史和目录保持。

重新连接原故障资产时，保存凭据和Host Key仍可用，新会话及SFTP成功。此后主窗口正常关闭、进程返回0、测试TCP连接归零。失败期间拦截退出与恢复后允许正常退出分别观察，未强杀应用替代正常关闭。
