# SFTP 下载目标所有权边界（2026-10-21）

## 原问题与影响范围

共享 Rust 核心的 `download_file_create_new_cancellable` 先以 `create_new` 打开目标；旧实现不论该步骤是否成功，只要整个下载返回错误，就对目标路径执行 `remove_file`。若上层规划路径后，另一个本机进程先创建同名文件，`create_new` 正确拒绝覆盖，但旧错误清理随后可能删掉**并非本次下载创建**的文件。这是源码可证明的竞态风险，不是已经观察到用户文件丢失；不能把之前“取消后无残留”的真机结果解释为这个边界已通过。

`7dfe8d7` 将创建与失败清理收束到同一辅助函数：只有 `create_new` 成功后才可能清理；打开远端或本机创建失败直接返回，不删目标。下载读/写/取消失败仍清理本次创建的部分文件。此修复作用于共用该 Rust checked SFTP 下载路径的客户端；不改变 Android SAF 文档提供方的独立清理策略。

同轮进一步审查发现上传侧对应问题：远端随机临时名以 `CREATE | EXCLUDE` 排他创建，旧代码在该创建失败后仍尝试删除临时路径。`b54adb9` 改为仅在排他创建成功后才允许失败清理；临时名随机并不能代替所有权证明。这里同样只确定源码风险，未观察到真实远端文件被误删。
