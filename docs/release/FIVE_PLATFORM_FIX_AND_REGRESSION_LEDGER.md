## 记账规则

- 后续每次修复或优化均追加一行：编号、日期、问题与安全边界、源码提交/候选构建、自动化结果、实际设备结果、Android/Windows 对照点及遗留风险。**代码已改、自动化通过、隔离 GUI 通过、真机通过、五端通过**是不同状态，不互相替代。
- 真机记录仅使用测试夹具代号，不写账号、凭据、令牌、主机地址、设备 UDID 或未脱敏请求/响应体。保留失败的原始分类和首次结果；重跑通过另记，不覆盖失败。
- Apple、Android、Windows 契约源码现已分别固化为 `c62b60f`、`e13b0be`、`7a2ca23`；这是**源码候选**，不是已签名分发包或五端验收。服务端隔离分支尚未部署，不能用线上旧服务替代新契约联调。
- 每次跨端操作都记录：五端安装包的提交和签名身份、服务端版本、操作方向、是否离线、操作前后活动/最近删除数量、本机凭据状态、持久队列与重复同步结果。永久删除及每个新实例的法律条款接受仍按实际操作时的确认规则执行。

## 优先复测顺序（Android、Windows 设备就绪后）

1. 固定安装包身份与服务端版本；用独立测试账户确认基线仅有原 RDP 活动资产，旧删除夹具在连续同步后不出现。记录本机凭据和待投递队列数量，不复制明文内容。
2. 先跑 `TS-01/02/04/09`：两端分别发起 SSH 软删除，另外四端拉取；核对活动列表、最近删除恰一条、本机凭据移除、三次重复同步不复活。Linux 不安全自动接受时必须记录人工冲突步骤，不能伪记自动通过。
3. 跑 `TS-05/06`：离线编辑与远端删除冲突、离线删除重连、阻断项 + 无关到期项、重启持久化、游标及修订链。所有永久拒绝要有脱敏 HTTP 状态和服务端稳定错误码，不存响应正文。
4. 跑 `TS-03/07/08`：选择框/确认框/编辑后名称、RDP 功能边界、敏感内容保护。随后对虚构夹具测试恢复和最终删除；永久删除仍需当次确认。
5. 跑 `SEC-01` 的 Host Key 变更/拒绝连接，Android 按 `docs/ANDROID_REAL_DEVICE_TEST_RECORD.md` 补 SFTP 上传、下载、取消、断网和无障碍；Windows 按 `WIN-01` 补签名安装、更新和原生库核对。
6. 跑 `SEC-02` 的 SSH 交互式验证码：Linux 隔离 GUI 已对真实主机完成密码＋码在线/重连再索码/取消；其余端先补单跳密码/密钥＋码，再测跳板机和目标机分别要码、错误码及取消；逐端核对无明文持久化，Windows/Android 必须补实体设备操作，Apple 客户端也须补真实 OTP 主机。详细用例见 [专项验收记录](SSH_SECOND_FACTOR_ACCEPTANCE.md)。
7. 隔离服务端契约上线到专用环境后再跑 `CT-01`；最后按 `REAL_DEVICE_ACCEPTANCE_PROTOCOL.md` 的五端矩阵和 `DESK-01` 的桌面并发门槛核对发布状态。
