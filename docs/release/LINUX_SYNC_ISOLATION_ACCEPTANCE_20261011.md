# Linux 跨实例同步隔离与状态证据（2026-10-11）

本记录只涉及专用测试账户、Linux 虚拟开发机上的隔离 QA 目录与本机 macOS 独立 QA 包。Linux 源码候选 `30c92bf` 基于 `d8f0007`，Ubuntu 隔离 Debug 二进制 SHA-256 `4fda88c4f7ce2ad17fd116b005538d93272b4312751c7f2ead241d9e966d3ae5`（先仅构建，后在下述全新 QA 目录运行 GUI；未安装为原版）；Mac 负向补验仍使用先前签名 QA 代码哈希 `e049a960…`。未修改线上服务、原 Linux 安装版、现有测试账户资产或原有同步队列；不记录账户凭据、资产地址、设备标识或原始 HTTP 内容。

## 旧失败保留与定位

先前旧 Linux QA 数据目录有 3 条本地资产，其中 2 条配置为 `account_synced`；另一新 QA 数据目录当时手动同步后仍为 0 条，界面曾显示同步健康。**0 条的原始观察不因本轮分析而改写为通过。**“已选择账户同步”仅是本机作用域，不能证明上传成功。

本轮只读核查先前两次 QA 启动命令及相应 XDG 目录：命令设置了 `XDG_DATA_HOME`、`XDG_CONFIG_HOME`、`XDG_CACHE_HOME`，但**漏设 `XDG_STATE_HOME`**。两个名义上独立的 QA 数据目录都没有自己的 `state/OrbitTerm/sync`；默认用户状态目录却存在同步状态，单一账户游标为 1198、资产元数据 19 项，持久队列 0 项。上述事实足以确认之前的“全新实例”并非全新的同步设备：本地资产目录与同步游标来自不同隔离边界，增量拉取可被旧游标跳过。它**不能单独证明**旧两条资产曾成功上传、云端此刻有哪些活动资产，或排除服务端其他问题。

源码审查另发现 Linux 内存同步会话在切换账户解锁时复用了前账户的拉取节流时间；拉取开始即记录时间，在服务端拉取或确认失败后的节流窗口仍可显示“云同步健康”。服务端非特定拒绝原样带入 `SyncError::Server(String)`，可显示并持久化到离线队列，既缺稳定 HTTP 分类又有不可信错误文字落盘风险。
