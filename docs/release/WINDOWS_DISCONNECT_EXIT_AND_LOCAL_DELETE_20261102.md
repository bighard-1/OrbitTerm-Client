# Windows 断开失败退出保护与本机删除反馈（2026-11-02）

承接 [Windows 正常断开与多会话验收](WINDOWS_DISCONNECT_RECOVERY_20261102.md)。本轮开始时 Windows 真机仍为已验签的 `4456ef8`；不能把上一轮正常 EOF／重连结果记为本轮内部失败 GUI 通过。

## 源码发现与修订

1. 本机资产删除确认缺少不可恢复说明；已补“不会进入最近删除，无法在应用内恢复”，并保留仅影响本机、清理本机凭据及不修改远端服务器的说明。
2. 已登录状态的删除完成反馈原来只按“是否登录”选择文案，本机删除也会错误声称已记录同步墓碑。现在按实际成功入队的墓碑数量与直接本机删除数量分别反馈；混合删除、墓碑记录失败后保留资产及凭据清理失败提示仍保留。
3. 源码审查发现 Windows 关闭窗口只保护活跃 SFTP／批量任务，没有保护未完成的连接释放。新增不持久化的工作区重试标记：断开开始设置，只有释放确认成功才清除；窗口退出检查全部工作区，待确认／失败时取消关闭并提示等待或回对应会话重试。切到空白或其他活跃标签不能绕过；已有退出确认也不能绕过这项检查。

没有改变线上服务、Android JNI 文件、认证／Host Key 校验或正常连接的退出行为。故障注入仅计划在私有源码副本，不能进入产品提交。

### 首次私有 Windows 故障 GUI：部分通过，发现新缺陷

固定 `8a53b25` 的 Windows 原生 CI `41560358846`：400 项测试通过，WinUI Release 和签名包生成成功；Linux `41560358801` 成功。用户当次授权本轮私有故障包及产品 QA 证书更新；产品 QA 此时仍为 `4456ef8`，没有把私有结果写为产品更新完成。

私有副本采用独立数据目录、两条虚构本机资产、受检只读局域网夹具，保持 Host Key 与安全保护。GUI 真实建立两连接后，在关闭第一会话时故意延迟释放并返回未确认：

- **通过部分**：进行中菜单禁用，窗口退出被拦截；切到第二条活跃会话仍收到新终端输出、能刷新新目录标记；失败后退出仍被拦截。恢复正常释放后可依次关闭原标签和另一会话，应用正常退出，夹具停止。
