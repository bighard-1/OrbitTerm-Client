# 服务端—五端客户端契约验收台账

更新：2026-10-09。此文档区分源码检查、自动化测试与真实设备联调；任何一项通过都不能替代另一项。

## 当前代码基线

- 服务端隔离工作树：`codex/server-maturity`，最新提交 `e7851d4`。服务端回执称隔离 PostgreSQL 上 `go test ./... -count=1`、`go vet ./...` 通过。该分支尚未推送或部署，线上环境不代表这套契约。
- 本客户端工作树：`codex/five-platform-integration`。Linux 墓碑冲突专项按本节下方的复验记录单独审查、提交；其他平台的待验收改动不随这次提交混入，客户端整体尚未推送或发布。
- 服务端成功响应 `data.must_change_password`：登录、刷新、管理员登录返回当前状态；改密成功返回 `false`。受限操作仍以 HTTP 403、`PASSWORD_CHANGE_REQUIRED` 为最终门禁。
- 会话契约：刷新令牌一次性轮换；改密和主密钥轮换后必须使用新访问令牌及新刷新令牌。HTTP 409 `REFRESH_IN_PROGRESS`、`AUTH_STATE_CHANGED` 不得当作普通同步冲突或盲目重试写入；HTTP 413 不得反复自动投递同一超限请求。
- `POST /api/v1/auth/logout` 仅撤销当前设备会话；其他设备需使用独立的全设备退出操作。客户端本地退出在离线时仍必须完成，并明确提示远端撤销未确认。
- 发布顺序必须是先在隔离环境验证并上线兼容的服务端契约、后发布客户端；当前线上服务尚未更新时，客户端退出的远端撤销可能返回 404，并应显示“未确认”而不能宣称撤销成功。

## 真机/跨端阻断门槛

Windows 完整测试在 301 项阶段有 1 项 `DiagnosticsCopyExportsSanitizedRuntimeState` 偶发失败；该项单独重跑通过，完整 301 项重跑也通过；新增迟到解锁测试后 302 项再次全部通过。此项视为测试稳定性待排查，不以重跑通过掩盖首次失败。

Linux 令牌竞态的源码与单测已覆盖「旧后台任务在退出后完成」「密钥环写入挂起时退出」「安全操作结束与退出清理交叠」「清除失败时保持暂停并允许重试」。密钥环真实实现依赖桌面会话和 libsecret 服务；容器单测仅证明应用层顺序与代际判定，不能替代 Linux 桌面真机上重复执行退出、切换账户、改密及同步的实测。

在服务端隔离分支部署到专用测试环境之前，下列项目只能标记为“待测”，不能写“已通过”：

1. 五端分别验证首次登录、重启后会话恢复、`must_change_password=true` 时仅允许改密或退出，受限 API 返回 403 后也不能继续同步。
2. 两端同时持有即将过期的访问令牌，前台操作与后台同步并发触发刷新；不得重复消费同一刷新令牌，也不得在退出/改密后恢复旧会话。
3. 离线退出、联网退出、远端撤销失败分别验证本地凭据清除与明确告警；“退出当前设备”不得误写成“退出所有设备”。
4. 每个平台各创建、修改、软删除、恢复、最终删除 SSH/RDP 非真实资产；按五端相互交叉同步，重复同步与离线重连后不得复活墓碑，也不得出现某端无法删除。
5. 409 并发刷新/安全状态变化、413 超限、401 过期、5xx/断网分别故障注入；确认队列不丢失、不盲重试永久失败、可恢复项有明确操作提示。
6. 对照记录客户端版本、服务端提交、测试环境、设备/系统版本、资产 ID（脱敏）、操作顺序、时间与结果。未经过这些实测，不能宣称“五端墓碑矩阵闭环”或“产品成熟度达标”。
