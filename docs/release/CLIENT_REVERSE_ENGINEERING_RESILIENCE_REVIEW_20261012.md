# 客户端逆向韧性审查（2026-10-12）

## 范围与结论

本审查依据用户提供的 [REA 对话](https://chatgpt.com/share/6acc9b01-37bc-83ea-9cc0-59451541fa73)、[REA 项目说明](https://github.com/morluto/rea)、本仓库的定向源码检查，以及 [OWASP MASVS-RESILIENCE](https://mas.owasp.org/MASVS/11-MASVS-RESILIENCE/)；未安装或运行 REA，未对正式账户、生产服务或第三方软件做逆向。对话中的“七层防护”是建议，不是本项目已实现或已验收的事实。

REA 可辅助分析安装包中的字符串、符号、伪代码、APK/.NET/Apple 包结构及运行行为；它降低了复现客户端流程的成本，但不会因为拿到安装包就自动获得服务端源代码、其他用户的钥匙串或服务器授权。已被用户授权的客户端进程在使用期间仍能接触本账户的解密数据；设备失陷、调试注入和录屏属于不同于“只拿到安装包”的更强威胁模型。**把客户端视为可读、可修改、可重放的非可信执行环境**，是本项目的核心约束；不能以“无法逆向”为安全保证。

## 本仓库已核对到的边界（源码证据，不等于发布验收）

- Apple `KeychainDataStore` 为新条目设置 `WhenUnlockedThisDeviceOnly`；`CredentialVault` 将密码和私钥从普通资产元数据分离。Android `SecureCredentialStore` 使用 Android KeyStore；Windows 凭据库代码使用当前用户 DPAPI；Linux 文档和实现使用 Secret Service。各端仍需以**实际发布包**核对备份、导出、调试配置及落盘/日志泄漏。
- Apple 同步身份指纹由账户＋主密码派生 HMAC；资产、凭据和私钥走端到端加密信封。该设计使同步服务不必持有明文 SSH 凭据，不能为了“防逆向”把解密钥匙或用户 SSH 密码移到服务端，否则会改变隐私承诺。
- Apple `AppSession` 为解锁/同步功能在设备 Keychain 保存可恢复的主密码密文及设备包装钥匙。它不在安装包中，但在**被攻陷且具同应用 Keychain 权限的运行环境**中不能当作不可导出的硬件边界。应专项评估生物识别/后台同步需求与降低可恢复主密码驻留之间的取舍，不得未经兼容性设计直接移除。
- `NetworkService` 使用 HTTPS 并支持用户确认的自定义服务地址；API URL、请求形状、错误码和同步算法均应视为可被分析。客户端 UI 的账户、墓碑或资产状态判断不能代替服务端对象级授权、幂等性和并发控制。
- 既有自动化、隔离 GUI 与 iPhone/macOS/Linux 测试，**未构成** Android/Windows 真机、正式签名发布包或服务端抗滥用验收。源码扫描也不能证明不存在任何硬编码秘密或运行时泄漏；需要面向最终产物的专项检查。
- 对独立 iOS QA `.19` 与后继 `.20` 的主可执行文件分别做**有限的静态字符串探针**：均未命中所查的 AWS/GitHub/支付密钥格式；各命中的 6 条私钥相关字符串均仅为短格式标记，不是完整密钥。此探针不覆盖未知密钥格式、资源/框架、运行内存，也不是正式包审计。`.19` 已被 `.20` 原位替换；所查 QA Development 签名含 `get-task-allow=true`，**符合 QA 调试用途但不得作为对外发行包**；正式签名仍须另验。

## 分级行动

| 优先级 | 工作与验收标准 | 边界/注意事项 |
| --- | --- | --- |
| P0：发布前 | 对正式五端产物做静态字符串/资源/调试符号/Manifest/entitlement 扫描，检查长期 API 密钥、私钥、测试凭据、源映射和 QA 开关；发现秘密即撤销/轮换，并追溯构建源。检查日志、诊断、崩溃、剪贴板和同步信封不含明文秘密。 | 本轮未完成五端产物扫描；只看源码或 QA 包不能关闭此项。 |
| P0：服务端契约 | 在隔离服务端验证每个资产读/改/删、恢复、墓碑、密钥轮换、同步游标与设备会话均从**服务端令牌身份**绑定账户及对象，不信客户端传入的账户/设备/权限字段；对跨账户 ID、重放、并发、过量请求及离线队列分别做负向测试。 | 不更新线上服务；需服务端项目独立审查与联调证据。不能宣称现网已通过。 |
| P1：设备失陷 | 审查可恢复主密码与包装钥匙的用途、Keychain/Keystore/DPAPI/Secret Service 可访问性、备份属性、解锁后的内存生存期和退出清理；用受控测试账户验证不影响五端 E2EE、MFA 交接和离线墓碑。 | 用户已解锁或设备已失陷时无法保证绝对保密；此项降低暴露面。 |
| P1：发布链 | 签名/公证、依赖锁定与来源校验、可复现候选、更新通道、QA/正式身份隔离；Android/Windows 到位后核对安装包的 debuggable、符号、日志及旧版降级行为。 | 混淆、反调试、反篡改只是加成本，不能替代对象授权或 E2EE。 |
| P2：可选增强 | 在服务端完成账户/设备契约后，评估 Apple App Attest 和 Google Play Integrity 作为高风险操作的**服务端验证风险信号**，先灰度观测再决定拦截；桌面端另设计可兼容的设备治理，不作跨端一刀切。 | 官方分发、模拟器、企业包、离线 Linux/Windows、可访问性和维修流程都可能受影响；不默认强制封禁。 |

## 后续对照

Android/Windows 真机优先核对：发布安装包不含秘密/调试能力；本地凭据库无法从普通应用数据中明文读取；恶意修改客户端参数或重放旧请求时服务端仍拒绝跨账户资产/墓碑/密钥操作；退出/换账户后令牌与离线队列不能借旧身份投递；篡改安装包不会被当成官方更新。Linux/macOS/iOS 用同一隔离服务端测试脚本对照，保留所有失败，不把客户端 UI 拒绝当成服务端拒绝。

最终判断：现有本地安全存储与 E2EE 是正确方向，但**不能据此声称对 REA 类工具“已防逆向”或“五端安全成熟度达标”**。先完成服务端对象授权和正式产物审计，再评估加壳/完整性措施的成本收益。
