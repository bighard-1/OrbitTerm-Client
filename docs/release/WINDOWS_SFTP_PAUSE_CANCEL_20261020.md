# Windows SFTP 暂停→取消专项（2026-10-20）

范围：Windows 10 测试机的独立 `OrbitTerm QA`，候选 `a7118c1`。Mac 上经用户当次授权短时启动仅允许测试机及本机访问的 SFTP 夹具；临时 ED25519 主机密钥由 Mac 本机独立计算指纹，并与 Windows 首连弹窗逐字核对后才信任。夹具仅含 128 MiB 虚构慢速文件、只读 SFTP 和不可执行命令的空会话，不提供真实文件或 shell。Windows 新增的 SSH 资产选择“仅此设备”，不进入账户同步。本文不记录主机地址、账户凭据或完整设备标识。

## 原包真机观察与失败保留

1. 首次夹具只有 SFTP、没有空会话：Windows QA 已通过主机密钥校验，SFTP 列出唯一虚构文件；终端停在连接校验，首次下载到约 1.7 MiB 后任务显示“传输已取消”。该次暂停点击与连接状态变化无法可靠区分，**不计暂停→取消通过**。
2. 加入不执行命令的空会话后，Windows QA 终端连接稳定，SFTP 仍仅列出虚构文件。此前已取消任务的“重试”可重新开始下载；再次从文件右键选择下载并选择本地目录时，GUI 两次提示“无法批量下载／请选择文件或文件夹，并指定有效的本地下载目录”。该选择器/上下文选择异常另保留，未据此修改真实文件。
3. 受控重试中，任务先显示“正在下载”，点击暂停后显示“已暂停”，进度约 1 MiB/128 MiB；随后点击取消，任务最终显示“传输已取消”，但顶层错误反馈为“批量下载部分失败：成功 0/1，失败 1”。**底层取消生效、批处理分类错误，原包此项未通过。**使用 Windows 文件资源管理器只读查看专用下载目录，显示为空（0 项），未留下可误用的部分文件。

夹具服务已定向停止，端口无监听；无真实资产、凭据或远端文件改动。Windows 仅本机 QA 资产和临时下载目录留待修复版复测后清理，不把当前观察记为五端通过。

## 源码修复候选与待验

`MainWindowViewModel.RunSftpBatchDownloadAsync` 在用户请求取消后可能收到 checked core 的 `SftpDownloadResult.Failed(sftp_transfer_cancelled)`，旧实现将其计入失败。候选改为当当前批次取消令牌已请求且结果为失败时转入现有取消分支，保留未完成项重试；新增确定性回归，模拟“暂停→首次取消→原生层返回取消错误包”，断言任务与批处理均显示“已取消”而不是“部分失败”。

- 源码：固定提交 `1c8b337`，已推送至 `codex/five-platform-integration`。
- 自动化：[Windows Client 固定提交 CI](https://github.com/bighard-1/OrbitTerm-Client/actions/runs/39418101173) 成功，包含安全单测、WinUI x64 Release 和内部签名测试 MSIX；[Linux Client](https://github.com/bighard-1/OrbitTerm-Client/actions/runs/39418101167) 成功。Security Gates 在本次读取时仍运行中，不能记为通过。本机无 `dotnet`，未另跑本机 Windows 单测。
- 构建：Windows CI 归档 SHA-256 `eb577a70e34d4a6422650e6e27e91d7514326d6dc5ff87fe6aea211cfbaf5306` 与 GitHub 摘要一致，ZIP 完整性通过；MSIX SHA-256 `fbf9557828397fe12d19db97d32632269245ca165202fe43213b95071abb9081` 与随包清单一致，内嵌签名者与随包测试证书指纹一致。网页下载事件等待超时，但文件实际落盘并经哈希验证；保留此工具反馈异常。不把这些离线校验代替 Windows 安装后的系统签名校验。
- 隔离 GUI：无新增结果。
- 真实设备：上述原包失败。修复候选的 `0.3.0.33` 测试 MSIX 已覆盖安装到 Windows 10 独立 QA：安装前现有 QA 应用数据完整备份并核对文件数；安装后系统报告 `Get-AppxPackage` 状态 `Ok`、MSIX 签名 `Valid` 且签名者与本次授权导入的测试证书一致，应用可启动，原仅本机夹具资产仍列在未分组。远程输入既有主密码被判错，已停止重试、等待用户在当前 QA 弹窗亲自解锁，因此**暂停→取消修复版真机行为仍待复测**；不可将安装验证记为功能通过。旧测试证书暂保留待运行验收后精确移除。
- 五端：本场景只是 Windows 传输队列专项，不证明 Android/iOS/macOS/Linux SFTP 或五端完整验收。Android 后续对照暂停/取消后的任务分类、残留文件、重试；Windows 修复版优先重跑同一夹具并核对取消后无完整残留文件及选择器异常。

## 修复版真机复测中发现的目录弹窗阻断

Windows `0.3.0.33` QA 经用户亲自解锁后，原“仅此设备”夹具资产仍在；重新连接同一临时主机密钥的只读 SFTP 夹具，唯一虚构文件可列出。右键“下载文件”打开系统“选择文件夹”窗口，选中经独立检查确实存在的专用下载目录并确认后，客户端再次提示“无法批量下载／请选择文件或文件夹，并指定有效的本地下载目录”，没有开始任务。**这是修复版真机新增确认的独立阻断，暂停→取消修复仍未得到真机结果。**

源码分析当时发现一条可能路径：下载按钮在打开异步系统目录弹窗之前依赖 `ListView` 的即时选中状态，但返回后才由 ViewModel 读取选择；弹窗焦点与侧栏重绘可使当前选择消失。**这不是经真机独立隔离证明的唯一根因**，后续还发现监控采样可能抢先使会话失效。`bc579db` 在弹窗前捕获具体工作区、SFTP 会话与文件对象，返回后严格验证仍是同一会话和当前目录成员，然后按捕获目标下载；会话或目录变化时安全拒绝。新增自动化模拟弹窗期间清空选中项，要求仍能下载原目标；移除原目录项时要求拒绝。Android 后续对照系统目录选择后传输目标是否保持、错误提示与取消队列状态。

- 固定修复提交 `bc579db` 已推送；[Windows Client CI](https://github.com/bighard-1/OrbitTerm-Client/actions/runs/39421158792) 成功，包含新增单测和测试 MSIX 构建。本机仍无 .NET SDK，未本机另跑。
- CI 归档 SHA-256 `0cb3fb09e874d829852921f256fcb1f2b9ee0c83fe7d459248fef5c86ae0c50f` 与 GitHub 摘要相符；内层 MSIX SHA-256 `eb165f12ecff6e55a8aca886baa0ef6a81e9611925448807b7bc7de50668f950` 与随包清单相符；内嵌签名者与附带测试证书一致。
- 用户授权后，Windows 10 独立 QA 再次在原位覆盖更新：安装前现有应用数据单独备份并核对文件数、远端包哈希核对通过；安装后系统包状态 `Ok`、签名 `Valid`，应用可启动。上一张测试证书已精确移除，目前只留本次 QA 的测试证书。用户亲自解锁后，原仅本机夹具资产仍在。

## 新版 Windows 真机复测与监控误断线候选

1. 在新版 QA 中临时关闭“自动刷新资源趋势”后，连接同一只读 SFTP 夹具，系统目录弹窗选中专用空目录，**下载任务实际启动**；此轮目录弹窗阻断不再复现。但因同时改变了源码与本机监控设置，不能独立归因于选择快照修复。
2. 慢速下载约 4.9 MiB/128 MiB 时点击暂停，任务显示“已暂停”；点击取消后顶层显示“批量下载已取消”，单项显示“已取消”。专用目录经 Windows 只读列举为 0 文件/0 字节。故 `1c8b337` 的**首次暂停→取消分类在 Windows 真机通过**，原包“部分失败”仍保留。
3. 恢复默认自动监控后，点击该取消任务的“重试”能再次开始下载；随后任务显示“连接已断开，可重新连接”，整个 SSH/SFTP 会话最终变成“未连接”。同一时刻 Mac 夹具端口仍监听，曾观测到已建立 TCP 连接；第二次取消未形成稳定完成态，专用目录再次只读列举为空。**重试/会话保持未通过**，不能把首次通过外推为完整传输闭环。
4. 源码中监控采样通过 SSH exec 执行；夹具明确拒绝命令但允许 SFTP。旧 ViewModel 将连续三次监控失败直接解释为整个会话失活并放弃 SSH/SFTP lease，符合这次现象。后继提交 `b921c58` 仅在连续监控失败且**独立 TCP 探测也确认不可达**时才断开；探测仍可达时只标记监控失败，保留终端/SFTP。新增“监控失败但 TCP 可达不丢会话”及“监控失败且 TCP 不可达仍断开”自动化。[Windows Client 固定 CI](https://github.com/bighard-1/OrbitTerm-Client/actions/runs/39432534662) 与 [Linux Client 固定 CI](https://github.com/bighard-1/OrbitTerm-Client/actions/runs/39432534699) 成功；Security Gates 读取时仍运行。真实 SSH 会话保活**仍待新版 Windows 真机**，不能仅由 CI 推断。

`b921c58` 的 Windows 测试归档 SHA-256 `2b190a5fc8390a353abc611bae123abfa5626daabe30162bce26fde5d61d55b6` 与 GitHub 摘要一致；ZIP 完整性通过，内层 MSIX SHA-256 `9a342ad0d33faf170cdd0f58f1ef70b7472a5994d58044086918f6350a62b363` 与随包清单一致，内嵌签名证书与附带测试证书字节哈希一致。此包签名证书不同于当前 Windows QA，导入与覆盖安装需新的当次确认；**尚未安装**。

隔离 GUI：本轮没有另行运行。五端完整验收未完成；Android 后续对照 SFTP-only 或禁用远端 exec 资产在监控失败、任务重试和取消时仍可用，且无临时文件残留。

本轮结束时已定向停止 Mac 临时 SFTP 服务，监听端口已核对无监听。Windows 仅本机测试资产、独立空下载目录和已备份的 QA 应用数据暂留给新包重测；临时夹具密钥不提交仓库，待专项最终验收后清理。
