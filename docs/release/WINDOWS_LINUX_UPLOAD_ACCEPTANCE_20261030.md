## Linux 延迟交互的目标归属修复候选

**源码发现，尚非 GUI 复现**：上传在文件选择器返回后才读取当前目录，并由通用执行器再次读取当前活跃 SFTP 句柄；单个／批量下载也在等待系统选择器后使用当前会话。重命名、权限、删除确认和文本编辑器保存存在同类延迟交互。即使资产 UUID 相同，重连后的 core 句柄也是另一连接，旧选择／确认不应授权它。

本节候选在已渲染目录上保存工作区、checked SSH／SFTP 句柄、规范目录及视图修订；开始新的目录请求立即使旧视图失效，只有所属请求成功才重新开放操作。系统选择器、文本提示、删除确认、预览／编辑均在等待前捕获目标，提交时重新核验，失败则说明“会话或目录已变化，本次操作未开始”，不会向另一目标发起 I/O。工作线程仅接收原句柄及原路径，不在异步返回后重定向。过期目录回执不覆盖新视图，新开的失效 SFTP 句柄会关闭；操作结束只在原会话显示反馈，不刷新另一目录。

新增回归测试用合成 dispatch 观察器核对：相同目标只向原句柄／目录提交一次；工作区、SSH、SFTP、目录或视图修订任一变化以及无有效目标均为零 I/O；同资产断线、认证中、重连、替换句柄或缺 SFTP 句柄不能拥有旧操作。格式和差异检查已通过；固定提交、Ubuntu 编译／完整测试／隔离 GUI 和 CI 回执待补。未更换任何真实设备安装包，未动原 Android JNI 工作树改动、正式版或线上服务。

此修复不新增跨工作区持久任务历史，不承诺取消已经开始的后台传输，也不改变 checked core 的远端快照／排他目标／清理规则。Android／Windows 后续应对照选择器期间切换会话、同资产重连、目录改变、取消、原目标不写入及重新明确选择后才可传输；五端完整验收未完成。
