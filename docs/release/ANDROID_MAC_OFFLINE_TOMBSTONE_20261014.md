# Android K60 × macOS QA 离线墓碑交叉验收（2026-10-14）

## 固定边界

- 客户端提交 `0796494`；K60 为独立 `com.orbitterm.android.qa` arm64 QA 包，不是正式签名包。Mac 为既有独立 QA 应用；两端不是同版发布候选。服务端仍为现有测试账户所连接的在线服务，未更新线上部署。
- 仅复用虚构资产 `OT-K60-Cross-20261014`。原 RDP、真实 Debian SSH 及其他测试资产不操作；本轮不做永久删除或主机连接。
- Mac QA 从最近删除恢复该条后，活动列表可见；用户在 K60 QA 手动同步两次并确认活动列表可见。此时双方在线，仅完成离线用例的前置基线。

## 断联预检与未完成结果

1. K60 经扩展坞的 ADB 当时显示已授权；系统初始 `airplane_mode_on=0`，`FIREWALL_CHAIN_OEM_DENY_3` 关闭，QA 包为 `allow`。对设备列出的 384 个已安装包逐一只读核对，该链上的非 `allow` 计数为 0。未修改 SIM、Wi-Fi、蓝牙、整机飞行模式或其他应用规则。
2. 先启动 5 分钟自动回滚兜底，再仅将 QA 包设为 `deny` 并启用该调试防火墙链。系统回读为 QA `deny`、链 `enabled`，ADB 仍在线；Mac QA 手动同步后虚构资产仍在，符合云端尚未收到删除的基线。**系统规则回读不等于应用请求已经被实际阻断的端到端证明。**
3. 用户在 K60 QA 资产页点了一次同步，当时未看到即时提示，因而没有继续删除。随后用户补充：在“设置→同步与诊断”看到“离线”；连续点击资产页同步图标失败后，应用才弹出“连接失败，无法建立网络连接…”一类通用提示。**先前无即时提示的失败观察保留**；这证明旧包反馈不直观，不能据此断定同步成功。用户还发现分组操作菜单有“删除分组”，资产列表却没有明显的单条“删除资产”入口；旧版单条删除实际藏在资产编辑页。离线删除、重连或墓碑回拉均未执行，故**离线交叉没有验收结果**。
4. 5 分钟兜底自动执行后，系统回读 QA `allow`、链 `disabled`，ADB 仍在线；网络设置恢复原状。虚构资产仍为活动测试夹具，待下一次受控离线用例；没有触碰真实资产。

## 下一轮操作门禁

- 用户准备好在 K60 操作时，先覆盖安装反馈/单条删除入口修复版独立 QA 包并核对界面；再开启短时 QA 专用断网。同步图标失败后应在资产页直接显示“等待网络”或“同步失败”反馈；再仅从**该虚构资产行**的资产操作菜单软删除，并在确认框核对资产名。离线删除后 K60 本机活动列表应立即消失，而 Mac 在线端仍应保留，证明删除未提前到云端。不要点分组的“删除分组”或“永久删除”。
- 立即恢复 QA 联网并核对系统规则原状；K60 连续同步、Mac 连续同步、K60 重启后再同步，均应不复活，且最近删除可见。若有失败，保留首次状态、队列分类与脱敏错误，不用重跑覆盖。
- Mac 发起的离线删除方向尚无安全的独立应用网络隔离通道，本轮不模拟为已测；Windows/iOS/Linux 及同版签名五端矩阵也仍未覆盖。

## 后续受控复测：K60 离线软删除 → Mac 接收墓碑

- Android 源码 `7eefc9c`，独立 QA arm64 APK SHA-256 `0a06bff487f6a76a84d22f875a11ff2cbc955e76b41c5b3ec0d57f9b67c45e29`。ADB 原位覆盖安装返回 `Success`，保留 QA 本机数据；这不是生产签名或五端同版包。上一节的旧包即时反馈失败仍保留。
- 新包 K60 GUI：展开 `OT-K60-Cross` 后，唯一虚构资产行的“资产操作→删除资产”菜单可见；二次确认框明确只将该资产移入最近删除并移除本机凭据。先点“取消”核对菜单/目标，不触碰分组删除。随后仅将 QA 包设为网络 `deny`、启用调试链，回读均吻合，未关闭整机网络；启动 6 分钟兜底回滚，最终已主动恢复并核对 QA `allow`、链 `disabled`，ADB 仍在线。首次误用调试命令的 `deny` 字符串被系统以 `Invalid boolean argument` 拒绝，规则尚未生效；改用文档要求的布尔参数后成功，此失败保留。
- 隔离期间 K60 点资产页同步，新横幅直接显示“同步失败：网络不可用，请检查网络后重试。”。用户随后亲自在 K60 仅软删除该虚构资产；本机活动列表即刻不再显示它，Mac QA 在线同步后仍显示它。**本轮未直接读取 K60 持久队列行；离线排队的结论由本机消失、Mac 仍在以及随后跨端传播推得。** 用户同时报告离线时“最近删除”无法使用；旧实现从云端实时读取回收站，断网时无法加载，不能把此误判为删除失败。
- 恢复 QA 网络后 K60 手动同步；Mac 第一次检查尚显示原活动资产，随后再次点同步，目标分组/资产从 Mac 活动列表消失；Mac 再同步未复活，最近删除里可见同一目标。**第一次检查仍在的中间状态保留**，不写成瞬时同步成功。K60 再次同步、强制结束独立 QA 进程并重启/主密码解锁、再同步，活动列表均未见目标；联网后 K60“最近删除”也能加载同一目标。只操作虚构资产，原 RDP 与真实 SSH 未删除/连接，未做永久删除。
- 结果：**Android K60 发起的离线软删除 → 重连发布墓碑 → macOS QA 接收 → 双端重复同步/Android 重启不复活，有限通过。** 尚无 Mac 发起的离线反向用例、同版/正式签名、Windows/Linux/iOS 本候选交叉，故五端矩阵仍开放。Android 回收站离线读取/即时撤销仍是能力边界：当前不缓存云端回收站，本机凭据按删除策略立即移除；若要支持离线恢复，需要单独设计加密保留与跨端冲突契约，不能在此测试中临时回退安全删除语义。Android/Windows 后续对照离线失败横幅、单资产与分组删除区分、回收站离线提示、重连后墓碑传播和重启不复活。
