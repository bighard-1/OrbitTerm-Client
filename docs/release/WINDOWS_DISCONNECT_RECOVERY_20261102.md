## Windows 真机 GUI：无注入正常包

仅使用 Mac 上限时、来源受限的虚构 SSH／只读 SFTP 夹具，沿用已核对的测试 Host Key。服务器不执行终端命令，不暴露真实文件。原测试资产加上一条本轮新增的“仅此设备”虚构资产建立两个独立工作区，以不同的终端序号和持续输出标记区分，不能只看相同端点的标签外观。

1. 两条连接均进入在线终端，SFTP 列出虚构目录。
2. 夹具仅对第一条终端发送正常 EOF，SSH 基础连接和另一工作区保留。原工作区显示“已准备就绪／打开终端”；第二条终端仍持续收到新输出，刷新 SFTP 可见 EOF 后才新增的目录标记。
3. 在第一条工作区显式“断开连接”，状态转为未连接；显式“重新连接”得到新的终端序号并重新列出 SFTP 目录，没有卡在无法释放状态。
4. 关闭第一条已连接标签后，它被移除；选中保留的第二条标签，仍是原终端序号、持续新输出及原 SFTP 目录。随后正常断开并关闭第二条，最终没有活动会话。
5. 删除本轮新建的虚构本机资产，原资产文件与 Host Key 文件逐字节保持，原 7 个凭据文件数量和摘要保持。最终恢复原 5 分组／7 资产，夹具进程和监听已停止。原有真实 Debian／RDP 等资产没有连接或修改。

本轮正常包未观察到断开／重连的产品缺陷。**没有制造 Windows 原生内部释放失败，因此不宣称“失败提示→重试”的 Windows GUI 已通过**；Linux 私有故障 GUI 的通过不能迁移为 Windows 的结果。

## 新增自动化回归

本轮仅修改 Windows 测试代码，不修改产品逻辑。`DisconnectAndRetryKeepAnotherLiveWorkspaceUsable` 两个分支使用不同基础会话 ID，覆盖：

- 第一条断开待确认时切换到另一条已连接工作区，另一条仍能接收和发送终端数据、读取 SFTP 目录。
- 第一条释放成功或失败后，不改变第二条所持终端／SFTP lease、当前路径与选中工作区。
- 失败重试只对原基础连接再次释放，不重复关闭已成功关闭的终端，不提前新建连接；完成后第二条仍可收到新输出。

结果：新增 2／2 通过；原断开专项 8／8 通过；完整 .NET 安全测试 **395 通过、0 失败、0 跳过**（macOS 上执行可移植测试及本地原生密码学库，**不是 Windows GUI**）。共享 Rust Release 的终端重复关闭与其他通道所有权 2／2 通过。新测试提交的远端 CI 另行核对，不能继承候选包的 CI 结果。

## 准备失败与未覆盖项

- 浏览器下载等待 90 秒超时，但后台下载继续，最终文件大小和 GitHub 摘要一致；仅以最终文件核销，不覆盖等待失败。
- RDP 批量输入丢失反斜线和部分字符；首条 PowerShell 命令解析失败，后续脚本文件被执行策略拒绝，均未开始安装。改用已审查的只读管理命令读取脚本内容，未修改系统执行策略。资产表单也发现远控输入错位，保存前逐字段清除、逐字符输入并核对，错误端点未保存。
- 首次安装命令因长度超出远程命令通道预算未实际创建安装进程，安装结果不存在、核心摘要仍为旧值；停止该本机等待，确认无在途远端进程后改为短入口，最终安装成功。旧等待不算安装成功。
- 旧证书清理命令的控制台进度产生编码告警，独立保存的 JSON 回执及再次验签确认清理成功；告警保留。
- 等待期间第一轮 20 分钟夹具自动关闭，原工作区显示未连接／连接未完成；重开同一受限夹具并由 GUI 显式重连后才开始上述双会话验收，不据此推导精确的断线检测时限。
- 收尾时 Windows “仅此设备”删除确认虽然说明只移除本机资产和凭据，但仍缺 Android 已有的“不会进入最近删除、无法在应用内恢复”直白说明，记录为后续交互一致性优化项；不把此文案缺项解释成墓碑机制失败。

**剩余范围**：Windows 内部释放失败／异常的受控 GUI 注入、失败后关闭意图及退出拦截仍待补；正常包 GUI 与自动化不能替代这部分。Android／iOS／macOS 对照待确认期间禁止提前重连、保留原资源、失败明确可重试、其他活跃会话可用及重复关闭幂等。K60 本轮开工只读检查在线但锁屏，没有解锁、安装或新增设备结果。五端完整验收仍未完成。
