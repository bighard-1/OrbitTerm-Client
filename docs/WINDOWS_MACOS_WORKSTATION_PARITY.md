# OrbitTerm Windows / macOS 桌面端功能与行为一致性契约

更新时间：2026-08-21  
范围：仅比较 Windows 与 macOS 桌面客户端。移动端不作为桌面布局基准。  
产品基准：两端属于同一桌面产品；信息架构、功能结果、安全语义和状态反馈必须一致，平台原生控件与系统能力允许不同。

## 状态定义

- `已对齐`：两端具备等价能力，结果与安全边界一致。
- `Windows 待补`：macOS 已形成完整闭环，Windows 尚缺功能或交互深度。
- `macOS 待补`：Windows 已形成更成熟的交互，macOS 尚未吸收。
- `双方待收敛`：两端都有实现，但协议、状态或验收口径尚未统一。
- `有意差异`：平台原生能力不同，不得为了外观一致而复制另一平台控件。

## 不可变产品规则

1. macOS 与 Windows 均采用“顶部全局区 + 左侧资产 + 中央会话 + 右侧工具”的三栏工作站。
2. SFTP、Docker、Snippets 只能作为当前会话的平级工具；不得各自创建未经 Host Key 验证的独立连接。
3. 当前会话切换后，监控、SFTP、Docker、Snippets 和当前资产 IP 必须原子切换，禁止显示前一会话数据。
4. 凭据、主密码、令牌、私钥、终端输出和远程路径不得进入普通配置、诊断或截图证据。
5. 平台差异只能改变控件表现，不得改变远端结果、安全确认、错误恢复和同步数据格式。
6. 任一端新增桌面功能时，必须同时登记另一端的实现、明确平台例外，或标记为待补；不得形成未登记的孤立功能。
