# OrbitTerm 三端桌面视觉一致性契约

适用范围：macOS、Windows、Linux 原生桌面客户端。

## 视觉裁决原则

三端不是相互复制皮肤，而是实现同一个紧凑专业运维工作台。Windows
工作台的布局密度、终端宽度保护和响应式折叠作为结构基准；macOS 的
颜色层次、认证聚焦和表面克制作为表现基准。用户已经验收的零宽度折叠、
同步状态常显、紧凑监控带和端点监控卡属于共享产品决策。

## 必须一致

- 顶部 Logo、全局操作的数量、顺序、相对权重和可达性。
- 端点与六项监控指标的顺序、卡片占比、曲线和详情入口。
- 资产栏、终端工作区、会话工具三栏结构及其响应式折叠顺序。
- 同步状态是位于三栏工作区之外的全宽独立底栏；三栏分割线必须在底栏上方终止，任何侧栏折叠都不得隐藏或改变底栏宽度。
- 标签、终端、命令预输入、SFTP、Docker 的信息层级，以及 Snippets 作为顶部全局功能的可达性。
- SFTP 顶部仅保留返回上级、路径、刷新和更多；目录级创建/上传进入“更多”与空白区右键菜单，文件级管理进入条目右键菜单。
- SFTP 传输任务固定在工具区底部并默认收起，只显示单行任务摘要。
- 登录、注册、解锁和同步管理的任务拆分及字段顺序。
- 设置分组顺序、五套应用主题、四套终端主题和语义状态色。
- 空、加载、失败、危险确认、禁用和焦点状态的视觉语义。

## 允许原生差异

- macOS 交通灯、Windows 标题栏按钮、Linux 桌面环境窗口按钮。
- SF Symbols、Segoe Fluent Icons 和 Freedesktop symbolic icons 的具体字形。
- 应用标志的主体、正方形比例和圆角轮廓必须一致；Linux 图标资源必须自带透明圆角，不依赖桌面环境代为裁切。
- San Francisco、Segoe UI Variable、Adwaita Sans 的字面度量差异。
- Command、Ctrl、Alt、Super 的平台惯用快捷键。
- Touch ID、Windows Hello、Secret Service 等平台能力入口。
- 原生文件选择器、通知、无障碍焦点框和系统高对比度呈现。

## 响应式验收矩阵

每端至少验证 980×700、1180×720、1280×800 和最大化四种状态。Linux
另外验证 820×560 紧凑状态，此时必须先收起侧栏以保护终端可用宽度。Windows
额外覆盖 100%、150%、200% DPI；macOS 覆盖标准与 Retina；Linux 覆盖
GNOME/Wayland 和 GNOME/X11。相同测试状态下，面板占比、控件顺序、
文本层级和功能可见性必须一致，字体像素栅格和原生窗口装饰不参与失败判定。

## 空状态与会话入口契约

- 无资产时统一显示“还没有服务器”，说明为“添加服务器后，即可从这里安全地发起连接。”。
- 无活动会话时统一显示“暂无会话”，说明为“从左侧选择服务器，然后建立连接。”。
- 会话标签栏只显示已发起连接的资产；Windows 为承载编辑状态保留的内部草稿不得显示为用户会话。
- 新会话统一从资产双击、资产右键菜单或工作台快捷键发起；空标签栏不放置脱离资产上下文的“+”按钮。
- Windows 在小于 1080px 的紧凑宽度下将账户入口收敛为原生账户图标，完整名称继续通过工具提示、键盘焦点与自动化名称提供。

## 合并前终审（2026-09-09）

本轮以 Linux 1280×720 桌面原生窗口、Linux 客户端内嵌 RDP 展示的
Windows 10 原生客户端，以及 macOS 当前构建的窗口几何与无障碍结构作为
证据。macOS 已启用 `NSWindowSharingType.none`，系统截图会按设计拒绝捕获；
该安全行为不应为了视觉审查而关闭。既有已验收截图只用于辅助定位，不作为
本轮新截图证据。

### 审查结论

| 项目 | 结论 | 严重度 | 处理 |
| --- | --- | --- | --- |
| 工作台骨架 | 三端均为顶部全局区、端点与六指标监控带、资产/会话/工具三栏；完整三栏以 980×700 为基准，Linux 另提供 820×560 自动收栏紧凑模式 | 通过 | 静态合同门禁 + Linux 原生尺寸断言 |
| 顶部全局操作 | Linux 曾为每项操作附加图标，较 macOS/Windows 的文本操作行更拥挤 | 中 | Linux 改为文字命令；Logo 与账户继续保留原生图标 |
| 监控语义 | Linux 第六项曾简写为“延迟”，macOS/Windows 为“TCP 延迟” | 中 | 统一为“TCP 延迟” |
| 配色 | 五套主题的名称、顺序和核心语义色一致；实机截图颜色差异来自各设备独立偏好 | 通过 | 保留用户偏好，不强制跨设备同步当前主题 |
| 原生窗口 | 交通灯、WinUI 标题栏按钮、GNOME 窗口按钮及其留白不同 | 有意差异 | 不复制另一平台的窗口控件 |
| 空状态 | 标题与说明完全一致；各端使用 SwiftUI、WinUI、Adwaita 的原生空状态容器 | 低风险原生差异 | 保留控件形态，继续保证文案、层级和动作可达 |

### 2026-09-09 细节对齐补充

- Snippets 从三端会话工具移至顶部命令区，位于“批量命令”和“设置”之间；未连接时仍可管理和同步，插入/执行按当前 SSH 会话能力启用。
- 会话工具标签统一只保留 SFTP、Docker，避免窄工具栏出现第三个长标签和功能归属混淆。
- macOS 监控带移除外层重复端点卡，端点与六项指标统一为 34 点高并按可用宽度等分。
- 网络速率三端统一按 orbit-core 的千比特语义显示，并在 Kbps / Mbps / Gbps 之间自适应切换。
- 三端左右恢复按钮统一使用工作区顶部 12 点内边距及 72 点交互高度。
- Linux 命令预输入的左边距改为读取侧栏实际可见性；侧栏收起时直接归零，不再保留历史宽度空洞。

### 自动化防漂移

`scripts/quality/check_desktop_visual_contract.py` 现在同时约束：

- 三端最小窗口、侧栏/终端/工具栏比例与宽度边界；
- 顶部八项全局操作的数量、顺序和 Linux 文本化密度；
- 端点后的 CPU、内存、磁盘、下载、上传、TCP 延迟顺序；
- 资产/会话空状态文案、SFTP/Docker 顺序，以及 Snippets 顶部独立入口；
- SFTP 紧凑工具栏、目录/条目右键管理和默认收起的传输任务；
- 左右恢复按钮位置，以及 Linux 侧栏收起后的命令预输入零偏移；
- 五套应用配色的名称和顺序。
- 根级全宽同步底栏的层级、顺序和紧凑高度，以及 Linux 三栏分割线不得穿过底栏；
- Linux Flatpak 六个 Hicolor 尺寸均来自专用图标集，且四角透明、中心不透明。

该检查进入 Ubuntu 客户端检查以及独立跨桌面发布门禁，未来任一端单独改动上述
合同都会直接失败。像素栅格、系统字体和窗口装饰不参与失败判定。

### 证据限制

截图可以确认层级、密度、溢出和相对比例，不能单独证明键盘顺序、屏幕阅读器
播报或所有高对比度组合。此类能力继续依赖 VoiceOver、Narrator、AT-SPI 和
三端原生焦点状态的实机门禁，不以“看起来一致”替代无障碍验证。
