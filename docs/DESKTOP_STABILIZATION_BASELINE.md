# OrbitTerm 桌面端稳定化基线

更新时间：2026-08-20  
适用范围：Windows 与 macOS 桌面客户端；同步数据契约同时约束 iOS 与 Android。  
阶段结论：冻结非必要新功能，优先关闭跨端一致性和并发性能风险。

## 冻结规则

1. 在 P0 阻塞项关闭前，不新增新的业务模块、协议或独立入口。
2. 允许的改动仅限：安全修复、数据一致性修复、性能与稳定性修复、无障碍、兼容性、测试和发布证据。
3. 已有功能的视觉调整不得改变加密信封、Host Key、凭据、会话和远端操作语义。
4. Windows 与 macOS 任一端改变桌面行为时，必须同步更新 `WINDOWS_MACOS_WORKSTATION_PARITY.md`。
5. 同步模型变更必须在 Apple、Windows、Android 三套合并路径上使用同一资产身份和墓碑优先规则。

## P0 阻塞项

### P0-1 跨端资产删除墓碑

- 统一身份：使用 `asset_id`，禁止使用每次上传生成的配置记录 ID 代替资产身份。
- 统一优先级：同一轮拉取同时出现 active 与 trash 时，trash 必须覆盖 active。
- 统一保护：本机待发布的编辑不得被静默删除，必须进入冲突状态。
- 统一结果：活动清单移除、最近删除保留、凭据安全删除、重复同步不得复活。
- 必测顺序：Windows 删除 → macOS/iOS/Android 拉取；macOS 删除 → Windows/Android 拉取；离线编辑与远端删除冲突。

### P0-2 大文件传输与交互并发

- 基准场景：三台资产、每台两个终端分屏、六路长输出，其中一台上传或下载 3 GiB 文件。
- UI 目标：窗口在 250 ms 内响应点击；终端不可出现空白窗格；会话切换不可超过 500 ms。
- 监控目标：所有趋势序列继续推进；连续两个采样周期无数据必须显示明确缺失态，不能保留旧值伪装在线。
- 传输目标：进度更新不得超过每秒 8 次进入 UI；传输不得因监控采样周期性永久降速。
- 资源目标：稳定运行 15 分钟无持续内存增长；取消任务在一次点击后 1 秒内进入取消中状态。
- 证据不得包含主机、账号、路径、命令、终端输出或凭据，只保留数值指标和构建版本。

## 发布阻塞项

- P0-1 尚未完成四端真机回归。
- P0-2 尚未形成 Win10、Win11 与 macOS 的同场景性能证据。
- Windows 正式签名证书及 HTTPS 更新地址尚未配置。
- macOS 正式签名、公证与发布候选证据仍按 Apple 发布门禁执行。
- Windows ARM64 尚未完成核心库、WinUI 与 MSIX 真机验证。

## 完成定义

只有同时满足以下条件，才允许恢复新功能开发：

1. P0 墓碑矩阵全部通过且重复同步不复活资产。
2. P0 性能场景在 Win10、Win11、macOS 各连续通过三次。
3. Windows 与 macOS 自动化测试及 Release 构建通过。
4. 技术债、功能矩阵、机器可读门禁和实机证据版本一致。
