# 技术债清单

## TD-20260804：跨端资产删除墓碑的全量收敛

- 状态：已恢复处理，阻断外部发布。
- 现象：Windows 删除资产并执行双向同步后，iOS 与 macOS 的“最近删除”可见对应记录，但活动资产列表仍可能保留该资产。
- 已确认：Windows 会正确发布删除墓碑。Apple 全量同步此前按配置记录 ID 合并活动清单和回收站，同一资产的两种记录 ID 不同时可能先删除后复活；现改为按 `asset_id` 合并且回收站优先。Android 现显式分页拉取回收站，不再依赖活动接口偶尔返回 deleted 记录，并将 Apple 大写 UUID、Windows/Android 小写 UUID 统一为同一资产身份；旧 Android 数据使用大小写无关查询并在写回时迁移为规范小写。Apple 14 项同步策略测试、Android 墓碑/身份测试和 Windows 墓碑测试均已通过。仍需四端真机跨端回归确认。
- 当前约束：在四端矩阵通过前，删除操作不应被视为跨端即时强一致；跨端删除仍需在各端人工确认。新增与编辑的双向同步继续按现有流程使用。
- 处理原则：不为兼容旧端而让 Windows 重新发布已删除资产；不允许删除墓碑覆盖本机尚未发布的新增/编辑队列；不记录或导出明文资产和凭据。
- 恢复条件：建立“活动清单 + 回收站分页 + 本地待发队列”三方合并的共享契约，并在 Windows、iOS、macOS、Android 的真机上验证新增、编辑、删除、删除后编辑、离线重连与重复同步。
- 验收标准：任一端删除并完成一次双向同步后，其他端的活动列表移除该资产、最近删除保留记录，且凭据随资产从本地安全存储移除；重复同步不得复活资产。

## TD-20260820：大文件传输与交互会话资源竞争

- 状态：处理中，阻断外部发布。
- 现象：高延迟资产上传速度可能从初始峰值逐渐回落；大文件传输与多终端持续输出同时运行时，终端流畅度、监控刷新和 UI 响应会相互影响。
- 当前实现：SFTP 使用受检验会话、有限缓冲、进度双层节流、按资产隔离队列；监控采样请求会促使上传管线排空并短暂让出调度。
- 风险假设：当前写入仍以顺序等待为主，高 RTT 下难以填满带宽时延积；监控触发的周期性 flush 可能进一步降低管线利用率。未经测量不得继续盲目扩大缓冲或并发窗口。
- 处理原则：保持终端与监控可交互优先；以脱敏数值证据评估吞吐、响应、内存和采样连续性；不通过取消 Host Key、会话隔离或安全替换来换取速度。
- 验收标准：三资产、六分屏、六路持续输出和单路 3 GiB 传输并行 15 分钟，在 Win10、Win11、macOS 连续三次无空白窗格、无 UI 卡死、无陈旧监控伪在线、无持续内存增长。
